# Минимализм кода

Перед тем как писать код, пройди лестницу молча (без пошагового нарратива) и остановись на первой подходящей ступени:

1. Это нужно прямо сейчас? Нет -> не пиши (YAGNI).
2. Уже есть в кодовой базе -> переиспользуй или расширь.
3. Есть в stdlib или нативных возможностях платформы (HTML, CSS, ОС) -> используй.
4. Есть в установленных зависимостях -> используй.
5. Иначе -> минимальное ясное изменение в стиле проекта.

Если выбор ступени 4-5 (новая зависимость, новое изменение) не самоочевиден - одной строкой скажи пользователю, почему предыдущие ступени не подошли.

## Никогда не режь ради краткости

Корректность, читаемость, необходимые тесты, валидацию на границах доверия (внешний ввод, API), security, защиту от потери данных, доступность (a11y).

## Принцип

Ленивый в решении - не ленивый в чтении: сначала изучи существующий код.

См. также `rules/karpathy-guidelines.md` (Simplicity First) - тот же принцип как общее правило поведения; здесь он оформлен как процедура выбора решения.
