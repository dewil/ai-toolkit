# asana-comments

Постраничное чтение комментариев (stories) задачи Asana через REST. Скрипт-эталон - `scripts/asana-comments.py` (top-level папка `scripts/` в корне проекта). Только stdlib, из внешнего - опционально `certifi`.

## Зачем это нужно поверх Asana MCP

У хостового Asana MCP (`mcp.asana.com/v2/mcp`) в схеме инструмента `get_task` параметр `comment_limit` описан буквально так: `"Max comments to return (1-50)"`, `maximum: 50`. Отдельного инструмента для чтения комментариев и курсора по ним нет - пагинация (`offset`) есть только у `get_tasks`, то есть для списка задач, а не для ленты.

Практическое следствие: **у задачи с большим числом комментариев часть ленты через MCP недостижима**. Опасность в том, что это выглядит не как обрезка, а как отсутствие комментариев - легко сделать ложный вывод "там ничего нет" по живой задаче. REST-эндпоинт `/tasks/{gid}/stories` пагинацию поддерживает, скрипт ее и разматывает.

## Когда применять

- В задаче много комментариев, а нужны свежие.
- Пользователь ссылается на комментарий, которого в выдаче MCP не видно.
- Нужен отбор по дате или вся история целиком.

## Когда НЕ применять

- Задачи, статусы, проекты, создание задач, **написание** комментария - это Asana MCP, у него OAuth из коробки и не нужен отдельный токен. Исключение - пакетное разворачивание/досыпка доски из JSON-плана: скилл `asana-project`.
- Задача короткая и MCP отдал ленту полностью - лишний канал не заводить.

## CLI

```bash
python3 scripts/asana-comments.py <task_gid>                  # последние 10 комментариев
python3 scripts/asana-comments.py <task_gid> --last 30
python3 scripts/asana-comments.py <task_gid> --all --system   # вся история + системные события
python3 scripts/asana-comments.py <task_gid> --since 2026-07-20
```

`task_gid` - последнее число в URL задачи.

Флаги:

- `--last <N>` - сколько последних показать (по умолчанию 10). Лента приходит от старых к новым, поэтому "последние" берутся с конца.
- `--all` - показать все, игнорируя `--last`.
- `--system` - включить системные события (назначения, смены статуса), а не только комментарии.
- `--since <YYYY-MM-DD>` - только начиная с этой даты, граница включительно.

## Авторизация: нужен именно Personal Access Token

Токен кладется в `~/.config/asana/auth.json` (`{"token": "..."}`, права 600) либо в переменную `ASANA_TOKEN`. Без токена скрипт печатает готовые команды настройки. Токен - секрет: в синкаемые папки, заметки, чаты и артефакты не класть (см. `rules/secrets-handling.md`).

**Как получить PAT - проговаривать пользователю по шагам, здесь ошибаются регулярно:**

1. Открыть консоль разработчика Asana - **корневую** страницу "Мои приложения" (не страницу конкретного приложения).
2. Прокрутить **ниже** списка приложений до блока "Личные токены доступа" / "Personal access tokens".
3. "+ Create new token" -> скопировать строку вида `2/...`. Показывается один раз.
4. **Не создавать приложение.** Кнопка "Create app" на виду и провоцирует пойти по ней, но credentials приложения к REST не подходят.

**Три способа получить 401, каждый пойман на живом инциденте:**

- **OAuth-токен самого MCP не работает против REST.** Он audience-bound к `mcp.asana.com`, а `app.asana.com/api/1.0` его не принимает. Лежит в `~/.claude/.credentials.json` -> `mcpOAuth`, refresh-токена рядом нет. Доставать его оттуда бессмысленно и хрупко.
- **client_id приложения** - это цифры. Не подходит.
- **client_secret приложения** - 32 hex-символа. Не подходит.

Отличать по форме: PAT длинный (50+ символов) и начинается с цифры и слэша (`2/...`). Если значение на это не похоже - выдан не тот секрет.

## Troubleshooting

- **401 при валидном на вид токене** - сверить форму значения по признакам выше. Чаще всего это client_id, client_secret или OAuth-токен MCP.
- **`CERTIFICATE_VERIFY_FAILED` на macOS** - сборка с python.org не видит системные CA. Скрипт сам подхватывает `certifi`, если тот установлен (`pip3 install --user certifi`).
- **Пусто по живой задаче** - проверить, не отфильтровал ли `--since`, и не нужен ли `--system`: по умолчанию показываются только комментарии, без системных событий.

## Граница с Asana MCP

MCP остается основным каналом работы с Asana. Этот скрипт закрывает ровно одну дыру - постраничное чтение ленты комментариев - и ничего не пишет: он read-only по своей природе (только GET). Вторая дыра MCP - пакетная запись (развернуть доску из плана целиком) - закрыта отдельным скиллом `asana-project` с тем же токеном.

## Связанные файлы

- `scripts/asana-comments.py` в корне проекта - эталонный скрипт.
- `~/.config/asana/auth.json` - PAT, вне репозитория, права 600.
- `rules/secrets-handling.md` - общее правило обращения с токенами.
