# Проверки для отдельно принятой задачи updater

Этот runbook применим только когда пользователь отдельно поручил updater и для него принята проектная спека. Он помогает проверить реализацию, но не задает архитектуру и не заменяет критерии приемки спеки. Если пункт противоречит проектной спеке, сначала разреши расхождение в SDD.

- Feed разбирай строго: отклоняй повторяющиеся JSON-ключи, неверные типы, неподдерживаемые версии и значения за project-defined bounds (включая размер, hash и signer). Проверяй redirect policy и отмену загрузки по спекам проекта; отмененный/частичный файл не становится готовым артефактом. Сбрасывай устаревший `ready`, когда изменился feed или идентичность артефакта.
- Разделяй проверку/скачивание APK и установку. Только отдельное явное действие пользователя запускает install. Связывай callback `PackageInstaller.Session` с активной сессией и уникальной identity `PendingIntent`; чужой, повторный или устаревший callback не завершает текущую операцию успешно. См. [`PackageInstaller.Session`](https://developer.android.com/reference/android/content/pm/PackageInstaller.Session).
- При повторном manual check обработай незакрытый результат по UI-контракту: показывай pending result, принимай ack только с совпадающим `resultId` и проверь, что ack снимает блокировку следующего ручного check. Устаревший или чужой `resultId` не подтверждает результат.
- Неизвестное или прерванное состояние сверяй с Package Manager и installer до отчета об успехе. Не трактуй неизвестность как `NOT_INSTALLED` и не запускай автоматический retry только из-за нее; при нерешенном статусе оставь операцию неопределенной для ручного восстановления. См. [`PackageInstaller.Session`](https://developer.android.com/reference/android/content/pm/PackageInstaller.Session).
- Восстанавливай persisted state через `AtomicFile.openRead()`, который обрабатывает backup; не предполагай, что base-файл уже существует. Не считай основной файл полным до recovery и проверки результата. См. [`AtomicFile`](https://developer.android.com/reference/android/util/AtomicFile).
- Докажи реальное обновление установленной версии N→N+1 с сохранением данных на матрице устройств и ОС проекта. Отделяй компиляцию, CI и запуск на устройстве; обязательный сценарий со статусом `NOTRUN` оставляет приемку открытой.
