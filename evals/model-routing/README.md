# Сценарии выбора модели SDD

cases.json — синтетические decision cases, не назначения и не разрешения на запуск. Их независимый оракул создан до изменения правила; expected/why никогда не передаются тестируемой модели.

Для проверки передай актуальный rules/model-routing.md, способности адаптеров и cases без expected/why в новый разрешенный read-only пакет. Факты fixtures задают вымышленный MODELS: primary — его предпочтение, held — только заданный HOLD. Живые назначения и квоты регулируют фактический вызов модели, но не подставляются в вымышленные случаи. Не выполнять выбранные маршруты.

Ответ: decisions с case_id, action select|block|hold, route_id либо null и причиной. block/hold не выбирают исполнитель: route_id=null. Сравнивать точные action/route_id с оракулом и проверять смысл причины; импорт/API-отказ и оборванный JSON не являются RED алгоритма. Для scope/доступа требуется отдельная проверка реальных источников, флаги фикстуры полномочий не дают.

Проверка на разных разрешенных моделях оценивает следование текстовому контракту. Actual model/effort/SID/usage подтверждает координатор. Она не доказывает доступность всех провайдеров и не заменяет CI или разрешение боевых действий. По умолчанию CI не вызывает платные модели.
