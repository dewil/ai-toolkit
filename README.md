# claude-toolkit

Канон правил, агентов и bootstrap-промтов для проектов с [Claude Code](https://claude.com/claude-code).

## Зачем

Claude Code из коробки - чистый помощник без памяти о твоих привычках. Чтобы он вел себя предсказуемо в проекте, обычно приходится: написать правила поведения, объяснить конвенции, описать субагентов под типовые задачи, настроить память. На один проект это полдня; на каждый новый - те же полдня заново. А правила, отлаженные в одном проекте, не доезжают до остальных - опыт не копится.

`claude-toolkit` решает это так:

- Канон правил, агентов и скиллов лежит в одном месте - в этом репо.
- Новый проект бутстрапается одной фразой: Claude фетчит канон по HTTP, раскладывает по `.claude/`, спрашивает про тип проекта (кодинг / документация / управление / учеба / claude-tooling / wiki) и докладывает специализированные файлы. Реестр накатанного хранится в `.claude/canon.yaml`.
- Существующий проект синкается с каноном: Claude сравнивает локальные снимки с upstream, показывает diff по каждому файлу, спрашивает "обновить?". Никаких симлинков и автоматических правок.
- Полезное, выработанное в конкретном проекте, можно вынести обратно в канон через upstream-pending брифы - проект сам соберет самодостаточный пакет для разработчика toolkit'а.

## Что это дает

- **Быстрый старт.** Новый проект готов к работе за минуты, сразу с типографикой, агентами и правилами под свой тип - без копирования снипетов из других проектов.
- **Накопление опыта.** Найденное в одном проекте правило переезжает в канон и через sync доходит до всех остальных. Эффект растет с числом проектов.
- **Согласованность.** Claude ведет себя одинаково во всех твоих проектах - одни кавычки, одни агенты, одни конвенции работы с документами и кодом.
- **Специализация под тип.** Кодовый проект получает правила тестов и обработки ошибок, документационный - copy-editor агента, claude-tooling - правила оформления промтов. Лишнее не тянется.
- **Под контролем.** Канон распространяется в виде явных снимков по HTTP. Любая правка - только после явного "ок". На свежем проекте sync отрабатывает как no-op.

## Для каких проектов

Это не только про код. Bootstrap спросит про тип и докинет специализацию поверх универсального набора:

- **coding** - кодовые проекты любого стека. Дополнительно тянет правила тестов и обработки ошибок, агентов `debugger`, `implementer`, `code-reviewer`. Пример: серверный сервис, библиотека, CLI-утилита.
- **documentation** - тексты, инструкции, базы знаний. Дополнительно тянет агента `copy-editor`. Пример: документация продукта, книга, технический блог.
- **management** - управленческие проекты, продуктовые задачи, планирование. Пока только универсальный набор (типографика, базовые агенты, правила работы с документами). Пример: roadmap-репо, продуктовые заметки, чек-листы релизов.
- **education** - учебные материалы, конспекты, разборы. Пока только универсальный набор. Пример: репо с заметками по предмету, конспекты лекций, разбор статей.
- **claude-tooling** - проекты-конструкторы для Claude (как сам `claude-toolkit`). Дополнительно тянет правила оформления промтов и агента `prompt-reviewer`. Пример: свой набор инструкций для команды, набор скиллов под рабочий процесс.
- **wiki** - Obsidian-vault'ы и персональные базы знаний. Дополнительно тянет правила формата заметки и перелинковки (`wiki-notes-style`, `wiki-linking-obsidian`), агентов `note-writer` (пишет заметки по конвенциям) и `librarian` (read-only ревизия vault'а: битые ссылки, дубли, сироты). Пример: заметки по велосипеду/здоровью/рецептам, личная wiki по теме, домашняя база знаний.

## Быстрый старт - новый проект

Открой Claude Code в корне нового проекта и скажи:

```
выполни инструкции из https://raw.githubusercontent.com/dewil/claude-toolkit/main/start.md
```

Дальше агент проведет через настройку памяти, базовых правил, агентов и специализацию под тип проекта (кодинг / управление / учеба / документация / claude-tooling / wiki).

## Обновление существующего проекта

Если проект уже бутстрапленный из этого toolkit (в `.claude/canon.yaml` есть запись), открой Claude Code в его корне и скажи:

```
сделай синк с canon
```

(или короче: `sync canon`)

Агент прочитает `.claude/canon.yaml`, скачает актуальные правила и агентов из этого репо, опишет расхождения по каждому файлу и спросит, что накатить. Заодно через [`manifest.yaml`](./manifest.yaml) проверит, появились ли в каноне новые файлы под тип проекта, и предложит их добавить. Логика - в [`migrations/sync-from-canon.prompt.md`](./migrations/sync-from-canon.prompt.md).

## Принципы

- **Идемпотентность** - любой промт безопасен при повторном запуске.
- **Audit -> plan -> "ок" -> action** - изменения только после явного подтверждения.
- **Изоляция** - проект ничего не знает о filesystem-расположении локального клона `claude-toolkit` на твоей машине.
- **Канон в одном экземпляре** - правила и агенты живут только в этом репо, не дублируются heredoc'ом.

Архитектурное описание - в [`CLAUDE.md`](./CLAUDE.md).

## Структура

- `start.md` - точка входа (тонкий роутер).
- `bootstrap/` - цепочка для настройки проекта с нуля.
- `rules/` - канонические правила поведения Claude.
- `agents/` - канонические описания субагентов.
- `skills/` - канонические скиллы (папка на скилл).
- `migrations/` - одноразовые промты для апгрейда существующих проектов.
- `manifest.yaml` - полный список канон-файлов по типам (для sync autodiscovery).

## Свой персональный toolkit

Этот репо рассчитан на то, чтобы его форкнули и допилили под себя - свои правила, своих агентов, свою типографику (например, английский вместо русского), свои конвенции. Идея в том, чтобы у каждого был свой канон, к которому подключаются его проекты.

**Как сделать свой:**

1. Форкни этот репо на GitHub под свой аккаунт - например `<твой-username>/claude-toolkit` (или назови как хочешь).
2. Замени `dewil/claude-toolkit` на свой `<username>/<repo>` в этих файлах:
   - [`start.md`](./start.md) - пример с `<canon_base>`.
   - [`bootstrap/bootstrap-01-memory.prompt.md`](./bootstrap/bootstrap-01-memory.prompt.md) - команда запуска.
   - [`bootstrap/bootstrap-02-scaffold.prompt.md`](./bootstrap/bootstrap-02-scaffold.prompt.md) - шаблон `canon.yaml` (поля `repo` и `raw_base`).
   - [`README.md`](./README.md) - команды в "Быстрый старт".
3. Закоммить и запушь в свой репо.
4. В новых проектах используй ссылку на свой `start.md`:
   ```
   выполни инструкции из https://raw.githubusercontent.com/<username>/<repo>/main/start.md
   ```

**Как наполнять своим:**

- Свои правила - в [`rules/`](./rules/), своих агентов - в [`agents/`](./agents/), свои скиллы - в [`skills/<имя>/SKILL.md`](./skills/).
- Любой новый файл регистрируй в [`manifest.yaml`](./manifest.yaml) в нужной секции (`universal` / `coding` / `documentation` / `claude-tooling` / `wiki` / `management` / `education`).
- Универсальные файлы дополнительно регистрируй в [`bootstrap/bootstrap-02-scaffold.prompt.md`](./bootstrap/bootstrap-02-scaffold.prompt.md); файлы под конкретный тип - в соответствующем `bootstrap-03-<тип>.prompt.md`. Подробности - в TODO-секции [`CLAUDE.md`](./CLAUDE.md).
- Лишнее из текущего канона можно удалить (например, если не работаешь с управленческими проектами - выкинь `bootstrap-03-management.prompt.md` и связанные строки из `manifest.yaml`).

После этого твои проекты будут синкаться с твоим каноном, а не с моим - и обновления будут приезжать те, которые ты сам туда положил.
