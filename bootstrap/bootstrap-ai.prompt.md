# Промт: новый проект с общим источником .AI

Этот маршрут - для нового проекта. Источник промта задает `<canon_base>` по HTTP; локальный клон не ищи. Старые проекты не мигрируй этим bootstrap. Миграция legacy в `.AI` - только по явному запросу через `migrations/ai-layout.prompt.md`. Шаги 01/02/03 относятся к legacy `.claude` и после этого маршрута не запускаются.

## 1. Аудит

Определи существующий корень клиента, типы из `manifest.yaml` и адаптеры (`claude`, `codex`, `kimi`) из запроса; уточни только недостающее. Контейнер Work не сканируй и не инициализируй. Подпроект отдельной идентичностью не наделяй. Проверь Linux и Python 3.11+: это первый проверяемый исполнительный контракт. macOS/Windows не объявляй поддержанными; DeepSeek без выбранной оболочки отвергается.

Обычный источник - `https://raw.githubusercontent.com/OWNER/REPO/COMMIT_SHA`, где SHA состоит из 40 hex-символов. Если start загружен с ветки, разреши ее в commit SHA через GitHub API, зафиксируй и покажи SHA; весь пакет, включая этот промт и скрипт, затем читай с этого SHA. Не подставляй `main` в исполняемую команду. При сетевом отказе остановись до изменений проекта. `--bundle DIR` допустим только для явно предоставленного снимка разработки/офлайн-проверки; сам искать клон запрещено.

До вызовов исполнителя проверь все три журнала, включая битые ссылки: `.ai-bootstrap/sync.json`, `.ai-bootstrap/migration.json`, `.ai-bootstrap/journal.json`. Несколько журналов - отказ без recover и удаления. При sync journal используй только `ai-sync.py check/recover --root ROOT` по `migrations/ai-sync.prompt.md`, затем заверши этот маршрут: bootstrap recover к нему не применяется. При migration journal действуй только по `migrations/ai-layout.prompt.md` и заверши bootstrap-маршрут. Эти проверки владельцев журналов имеют приоритет над обычной диагностикой среды.

Скачай `scripts/ai-bootstrap.py` из того же закрепленного источника во временное место, например `/tmp/ai-bootstrap.py`. Не копируй настройки агента, разрешения, секреты или глобальную память. Перед выводом о legacy по видимым `.claude`, `.agents`, AGENTS.md, CLAUDE.md или конфликтующим scripts выполни read-only `python3 /tmp/ai-bootstrap.py check --root ROOT` этим pinned helper. Проверка mount boundary идет до чтения клиентских данных. Если она сообщает `Environment blocked by mountpoint PATH`, не классифицируй видимую `.agents` или другой закрытый путь как legacy; прекрати работу в sandbox и попроси повторить именно эту команду из обычного терминала. Если она сообщает `Environment mount check failed` из-за недоступного или некорректного mountinfo, состояние host filesystem остается неизвестным: не делай вывод о legacy или чистой среде. Остановись и попроси выполнить ту же read-only команду в обычном терминале. Если команда уже запускалась из обычного терминала или отказ повторился там, сообщи диагностику helper и оставь состояние неизвестным; не запускай повторные попытки по кругу и не обходи проверку. Не удаляй маски, не меняй sandbox policy и не подключай удаленное исполнение. Успешная загрузка helper по сети не подтверждает доступ к host filesystem. Ошибка о незаполненном/отсутствующем состоянии сама по себе не означает mount-отказ и не доказывает legacy: после чистой проверки среды продолжай обычный аудит. Чистый новый root без следов установки может перейти к плану; реальные legacy-данные сохраняй и направляй только в отдельную согласованную миграцию. Настоящий `.agents` с данными не перезаписывай.

Если есть `.ai-bootstrap/migration.json`, останови bootstrap: используй `ai-migrate.py check/recover --root ROOT` по отдельной процедуре `migrations/ai-layout.prompt.md`. Не запускай bootstrap check/build/recover при migration journal; восстановление должно входить в согласованную операцию. Если есть `.AI` либо `.ai-bootstrap` (включая ссылку) без migration journal, это уже новый контур: выполни только `check --root ROOT`. При успехе сообщи сохраненный project_id из `.AI/project.json` и заверши маршрут: не создавай UUID и не запускай plan/apply повторно. Если пользователь явно запросил повтор идентичной установки, используй сохраненные ID и конфигурацию; изменение конфигурации требует отдельной миграции. При незавершенной операции сначала покажи результат check; `recover` выполняй только если восстановление входит в уже согласованную операцию, иначе получи подтверждение конкретного восстановления. После recover повтори check и заверши маршрут. При иной ошибке сообщи ее и остановись, не перезаписывай поврежденные источники. Legacy-инструменты не запускай. Реальные `.claude`, `.agents`, AGENTS.md, CLAUDE.md или конфликтующие scripts требуют отдельной миграции, а не удаления.

## 2. План

Если обнаружен `.ai-bootstrap` без журнала, bootstrap оставляет все артефакты на месте: автоматическое воспроизведение невозможно. Сначала выполни read-only инвентаризацию содержимого и прими отдельное ручное решение; один файл `lock` не доказывает, что процесс остановлен, и не является основанием для миграции.

Только для нового проекта без следов установки создай UUID один раз, сохрани его для plan/apply. Запусти (подставив реальные значения, а не угловые скобки):

```text
python3 /tmp/ai-bootstrap.py plan --root ROOT --source-base PINNED_URL --project-id UUID --types coding,wiki --adapters claude,codex,kimi
```

Типы и адаптеры в примере замени согласованным набором. План получает и валидирует полный пакет, но не пишет в проект. Сохрани JSON-вывод плана в файл вне проекта и покажи человеку краткую сводку: источник, состав universal+типов, затрагиваемые пути, коллизии, сохранение существующих данных и бюджет. Не выводи сырой JSON вместо сводки. Получи подтверждение конкретного плана, если оно еще не дано пользователем; повторного разрешения на уже согласованную работу не проси. Сам выполни уже разрешенные доступные загрузку, создание UUID, plan, apply, build и check; не перекладывай их на пользователя.

## 3. Применение и проверка

Выполни `apply` с теми же аргументами, затем `check --root ROOT`. При прерывании используй `recover --root ROOT` и повтори check; журнал не удаляй вручную. Повтор совпадающей установки - no-op; изменение конфигурации - отдельный переход, обычный canon-sync его не выполняет.

Канонические источники копируются точными байтами в `.AI/`, agents - в `.AI/roles/`, scripts - в `scripts/`. `.claude/{rules,skills,agents,commands,memory}` и `.agents/skills` - ссылки на общий источник. Шаблоны проекта и памяти становятся локальными файлами. `.AI/canon/canon.state.json` - единственный новый state; legacy-реестр не создается. AGENTS.md/CLAUDE.md генерируются: обязательные правила включены целиком по context-policy, остальное маршрутизируется START. Приватный project.md и память читаются напрямую, не встраиваются.

Заполни локальный `.AI/project.md` известными данными без секретов, оставив неизвестное TODO. Для дальнейшей правки входов меняй источники и запускай `build --root ROOT`, затем check. Ручные изменения генерируемого входа блокируют сборку.

## 4. Подключение среды

Установка файловой структуры успешна после `apply`, нужного `build` и `check --root ROOT` со статусом OK. Выполни доступные проверки текущего выбранного агента; остальные настроенные адаптеры отметь `NOTRUN`. Это не доказывает их подключение и не задерживает завершение установки. Если текущую runtime-проверку выполнить нельзя, отметь ее `NOTRUN`, укажи конкретное препятствие и дай не более одного минимального следующего шага для выбранного агента; не требуй проходить вручную матрицу оболочек или пересылать логи.

Чтобы утверждать, что адаптер подключен, нужна отдельная проверка в свежей сессии из корня: чтение входа, project_id, общей памяти и Markdown-задачи, затем запись тестового факта и его чтение следующей сессией. Если пользователь явно запросил проверку нескольких адаптеров, веди ее как отдельную задачу; неисполненные проверки остаются `NOTRUN`, а не `PASS`. Структурный check эту проверку не заменяет. Глобальная нативная автопамять автоматически не настраивается: до отдельного подключения и проверки используй `.AI/memory/` явно. Новая `.AI` автоматически не подключается к глобальному векторному индексу. Индексатор и Linux-расписание не меняются; после отдельного подключения возможна задержка индексации. До подключения работа идет по файловой памяти с явным ограничением поиска.

Сообщи корень, ID, SHA, выбранные типы/адаптеры, результат check и непроверенные среды. Обновление установленного `.AI` - навык `canon-sync` и отдельная `migrations/ai-sync.prompt.md`; `/canon` направляет к ним. Canon-delta/canon-migrate и старые sync/bootstrap здесь заблокированы. README и существующие документы bootstrap не переписывает.
