# Промт: scaffold для проектов документации

Этот файл - инструкция для Claude Code. Запускать **после** `bootstrap-02-scaffold.prompt.md`: открой Claude Code в **корне проекта** и попроси выполнить этот файл (например: `выполни инструкции из <путь>/bootstrap-03-documentation.prompt.md`).

Промт безопасен для существующих проектов. Сначала аудит, действия - после "ок". Существующие файлы не перезаписываются.

Добавляет к общему scaffold:

- агента: `copy-editor` (вычитка текстов на читаемость и единообразие)
- локальный шаблон `rules/style-guide.md` (тон, структура, термины - заполняется проектом)
- `@-`ссылку на `style-guide.md` в `CLAUDE.md`
- allow для генераторов статсайтов в `.claude/settings.json` (по подтверждению, по стеку)

КОНТЕКСТ ЦЕПОЧКИ. Это шаг 03. **Источник этого файла** (URL или локальный путь) определяет базу для канонических файлов:

- `canon_base` = подняться на один уровень из `bootstrap/`. Например, если этот файл загружен по URL `.../main/bootstrap/bootstrap-03-documentation.prompt.md`, то `canon_base = .../main/`.
- Канонические агенты специализации: `<canon_base>/agents/*.md`.
- Предыдущий шаг (сиблинг): `bootstrap-02-scaffold.prompt.md` в той же папке.

Ты в корне проекта документации. Раскатываешь специализацию scaffold под документацию: агент-корректор, шаблон стайлгайда, allow под генераторы. Базовый scaffold должен быть уже на месте (bootstrap-02-scaffold).

ВАЖНО. Промт безопасен для существующих проектов. Сначала аудит, потом план, потом ждешь "ок", только потом действуешь. Существующие файлы НЕ перезаписываешь.

ШАГ 2. Целевое состояние.

A. .claude/agents/ (источник - `<canon_base>/agents/`):

B. .claude/rules/:

E. .claude/settings.json дополнен allow для генератора статсайта по результату аудита (предложение, по подтверждению).

ШАГ 3. План.

Для CLAUDE.md - если файла нет или нет ссылки `@.claude/rules/style-guide.md` - покажи, что добавишь.

Для canon.yaml - покажи, какую запись допишешь в `files`.

Жди "ок". Без подтверждения - не действуй.

ШАГ 4. Действуй (после "ок").

### 4a. Скопируй канонического агента из `<canon_base>`

Если `copy-editor.md` еще нет в проекте:

- Если этот промт загружен по HTTP: `WebFetch <canon_base>/agents/copy-editor.md` -> запиши в `.claude/agents/copy-editor.md`.
- Локально (если читался с диска): `cp <canon_base>/agents/copy-editor.md .claude/agents/copy-editor.md`.

Существующие файлы НЕ перезаписываются. Для апгрейда к актуальной версии канона есть `migrations/sync-from-canon.prompt.md`.

### 4b. Создай `.claude/rules/style-guide.md` (если отсутствует)

```markdown
---
description: Стайлгайд проекта - тон, структура, единые термины
---

# Стайлгайд

TODO: заполни правила оформления текстов проекта.

- **Тон:** (например, нейтрально-деловой; обращение на "вы"/без обращения).
- **Структура документа:** (заголовки, порядок секций, длина абзацев).
- **Единые термины:** (как называть ключевые сущности; чего избегать).
- **Оформление ссылок и сносок:** (стиль ссылок, сноски, перекрестные ссылки).
- **Код и команды в тексте:** (когда инлайн, когда блок).
```

Это локальный файл, не из канона - каждый проект заполняет его сам. В `canon.yaml.local_only` не пишем (по умолчанию это понятно).

### 4c. Допиши `.claude/canon.yaml`

В секцию `files` добавь запись, которой там еще нет:

```yaml

```

Если `canon.yaml` нет - значит bootstrap-02 не выполнялся; сообщи об этом и не создавай `canon.yaml` сам (это работа шага 02).

### 4d. Дополни существующие файлы
