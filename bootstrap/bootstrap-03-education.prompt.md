# Промт: scaffold для учебных проектов

Этот файл - инструкция для Claude Code. Запускать **после** `bootstrap-02-scaffold.prompt.md`: открой Claude Code в **корне проекта** и попроси выполнить этот файл (например: `выполни инструкции из <путь>/bootstrap-03-education.prompt.md`).

Промт безопасен для существующих проектов. Сначала аудит, действия - после "ок". Существующие файлы не перезаписываются.

Для проектов учебных курсов: AI помогает вести конспекты по транскриптам лекций, разбираться с домашками, готовиться к экзаменам.

Добавляет к общему scaffold:

- агентов: `note-taker` (конспект из стенограммы), `tutor` (помощь с домашкой без решения за студента)
- правила: `lecture-notes.md`, `homework.md`, `course-structure.md`
- папки: `Лекции/`, `Конспекты/`, `Домашки/`, `Источники/`
- `@-`ссылки на новые правила в `CLAUDE.md`

---

КОНТЕКСТ ЦЕПОЧКИ. Это шаг 03. **Источник этого файла** (URL или локальный путь) определяет базу для канонических файлов:

- `canon_base` = подняться на один уровень из `bootstrap/`. Например, если этот файл загружен по URL `.../main/bootstrap/bootstrap-03-education.prompt.md`, то `canon_base = .../main/`.
- Канонические агенты и правила специализации: `<canon_base>/agents/*.md`, `<canon_base>/rules/*.md`.
- Предыдущий шаг (сиблинг): `bootstrap-02-scaffold.prompt.md` в той же папке.

Ты в корне учебного проекта. Раскатываешь специализацию scaffold под учебу: агенты для конспекта и помощи с домашкой, правила формата конспектов и работы с дз, структура папок курса. Базовый scaffold должен быть уже на месте (bootstrap-02-scaffold).

ВАЖНО. Промт безопасен для существующих проектов. Сначала аудит, потом план, потом ждешь "ок", только потом действуешь. Существующие файлы НЕ перезаписываешь.

ШАГ 1. Аудит (только чтение).

- pwd - корень проекта.
- Перечисли существующие:
  - .claude/agents/note-taker.md, tutor.md
  - .claude/rules/lecture-notes.md, homework.md, course-structure.md
  - .claude/canon.yaml - есть ли (должен быть после bootstrap-02), что в `files`
  - CLAUDE.md - какие @-ссылки уже есть
  - Папки Лекции/, Конспекты/, Домашки/, Источники/
  - Если в Лекции/ или Конспекты/ что-то есть - посмотри top-3 файла, чтобы понять формат, и сообщи. Не правь.

ШАГ 2. Целевое состояние.

A. .claude/agents/ (источник - `<canon_base>/agents/`):
   - note-taker.md
   - tutor.md

B. .claude/rules/ (источник - `<canon_base>/rules/`):
   - lecture-notes.md
   - homework.md
   - course-structure.md

C. CLAUDE.md содержит ссылки `@.claude/rules/lecture-notes.md`, `@.claude/rules/homework.md`, `@.claude/rules/course-structure.md`.

D. Папки в корне: Лекции/, Конспекты/, Домашки/, Источники/.

E. `.claude/canon.yaml`:
   - `files` содержит 5 файлов специализации (3 rules + 2 agents).
   - `project_type` - список, и `education` в нем (если списка нет/пустой - инициализируется на ШАГ 4; если `education` отсутствует среди других типов - добавляется на ШАГ 4).

ШАГ 3. План.

Таблица: файл / папка / действие / статус. Для существующих - "не трону". Для отсутствующих - "создам".

Если в Лекции/ или Конспекты/ обнаружен другой формат - укажи: "формат отличается от шаблона, что делать - пропустить правило или адаптировать?". Жди ответа.

Для CLAUDE.md - если файла нет или нет нужных @-ссылок - покажи, что добавишь.

Для canon.yaml - покажи, какие 5 записей допишешь в `files`.

Жди "ок". Без подтверждения - не действуй.

ШАГ 4. Действуй (после "ок").

### 4a. Скопируй канонических агентов и правила из `<canon_base>`

Для каждого файла из ШАГ 2 (A + B), которого еще нет в проекте:

- Если этот промт загружен по HTTP: `WebFetch <canon_base>/agents/<имя>.md` -> запиши в `.claude/agents/<имя>.md`. Аналогично для `<canon_base>/rules/<имя>.md` -> `.claude/rules/<имя>.md`.
- Локально (если читался с диска): `cp <canon_base>/agents/<имя>.md .claude/agents/<имя>.md`. Аналогично для rules.

Существующие файлы НЕ перезаписываются. Для апгрейда к актуальной версии канона есть `migrations/sync-from-canon.prompt.md`.

### 4b. Создай папки (если отсутствуют)

`Лекции/`, `Конспекты/`, `Домашки/`, `Источники/` с `.gitkeep` в каждой.

### 4c. Допиши `.claude/canon.yaml`

В секцию `files` добавь записи, которых там еще нет:

```yaml
  - rules/lecture-notes.md
  - rules/homework.md
  - rules/course-structure.md
  - agents/note-taker.md
  - agents/tutor.md
```

Если `canon.yaml` нет - значит bootstrap-02 не выполнялся; сообщи об этом и не создавай `canon.yaml` сам (это работа шага 02).

Отдельно про `project_type` (всегда **список**):

- Если поля нет вообще или это пустой список `[]` - инициализируй `project_type: [education]`.
- Если поле уже содержит `education` - не трогай (идемпотентность).
- Если поле содержит другие типы, но без `education` - **добавь** `education` в конец списка. Это нормальный случай мультиспециализации; не "миграция типа", не спрашивай - добавляй.
- Если поле - скаляр-строка (старый формат до перехода на список) - перепиши в список и добавь `education`. Сообщи в отчете о миграции формата.

### 4d. Дополни существующие файлы

Дополнения CLAUDE.md (ссылки на новые правила) - по отдельному "ок".
