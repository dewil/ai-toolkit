# Промт: bootstrap шаг 01 - настроить локальную автопамять

Этот файл - шаг 01 в bootstrap-цепочке claude-toolkit. Обычно запускается через `start.md` (точка входа репо), но может быть вызван и напрямую:

- По HTTP: `выполни инструкции из https://raw.githubusercontent.com/dewil/claude-toolkit/main/bootstrap/bootstrap-01-memory.prompt.md`
- Локально (если есть клон): `выполни инструкции из <путь до клона>/bootstrap/bootstrap-01-memory.prompt.md`

Промт безопасен для существующих проектов: сначала аудит и план, действия - только после твоего "ок". Если все уже настроено - агент подтвердит и ничего не тронет. Применяется к проектам любого типа (кодовые, управленческие, учебные, документация, claude-tooling).

---

КОНТЕКСТ ЦЕПОЧКИ. Это шаг 01 в bootstrap-цепочке. Следующие шаги - сиблинги в той же папке `bootstrap/`:

- `bootstrap-02-scaffold.prompt.md` - общий scaffold (правила, агенты, settings.json, CLAUDE.md, canon.yaml).
- `bootstrap-03-{coding,management,education,documentation,claude-tooling}.prompt.md` - специализация по типу проекта.

Базовый путь/URL соседей выводи **из источника этого файла**:

- `canon_base` = подняться на один уровень из `bootstrap/`. Если файл загружен по URL `.../main/bootstrap/bootstrap-01-memory.prompt.md` -> `canon_base = .../main/`.
- Сиблинги по `bootstrap/`: `<canon_base>/bootstrap/<имя>.prompt.md`.
- Канонические rules/agents: `<canon_base>/rules/<name>.md`, `<canon_base>/agents/<name>.md`.

Не спрашивай у пользователя путь к следующему шагу. Спрашивай только если по выведенному адресу файла физически нет.

Ты находишься в корне проекта. Цель - настроить локальную автопамять: симлинк ~/.claude/projects/<хеш>/memory -> .claude/memory/. Папка проекта синкается между устройствами через облако, глобальный путь у каждой машины свой и не синкается; симлинк делает стандартный путь Claude локальным для проекта. Симлинк не синкается - на каждом новом устройстве его создают заново.

ВАЖНО. Этот промт может запускаться в существующем проекте. Никаких изменений до моего явного "ок". Сначала аудит, потом план с подтверждением, и только после "ок" - действия. Файлы, которые ты не создавал и не должен трогать, - не трогай.

ШАГ 1. Аудит (только чтение, ничего не меняй).

- pwd -> PROJECT.
- Признаки корня проекта: CLAUDE.md или .claude/. Если ни одного - остановись и сообщи.
- Хост: рассчитан на macOS и Linux (Ubuntu и подобные). Если на сервере что-то непонятное (нет `ln -s`, нет `readlink` нужного формата) - сообщи и не действуй.
- Вычисли:
  - LOCAL = "$PROJECT/.claude/memory"
  - HASH = `echo "$PROJECT" | sed 's|[^A-Za-z0-9]|-|g'`
  - GLOBAL = "$HOME/.claude/projects/$HASH/memory"
- Проверь состояние через `ls -la`, `readlink`, `stat`, `[ -L ]`, `[ -d ]`, `[ -f ]`.
- Дополнительно: посмотри `~/.claude/projects/`, нет ли там папок с похожим, но не совпадающим именем (могут быть от старых версий Claude или от другого хеширования). Если есть - покажи top-3 ближайших; не трогай.

ШАГ 2. Сформируй план.

Целевое состояние - четыре условия:
1. GLOBAL - симлинк на LOCAL.
2. LOCAL содержит MEMORY.md.
3. LOCAL содержит feedback_local_paths.md (правило про локальные пути файлов, см. ШАГ 6).
4. Существует .claude/rules/typography-ru.md (правило типографики для русских текстов, см. ШАГ 7). Применяется в проектах любого типа, поэтому ставится здесь, до основного scaffold. Если файл уже есть - в ШАГ 7 проверь, нет ли в нем устаревшей формулировки правила про тире.

Для каждого условия укажи статус: ok / создать / изменить / коллизия. Сопоставь с кейсами ниже и выбери один.

Кейсы для GLOBAL:
- LOCAL не существует -> mkdir -p "$LOCAL"; создать MEMORY.md с одной строкой `# Memory` (если внутри уже есть файлы - не трогай).
- GLOBAL = симлинк на LOCAL -> ничего не делай.
- GLOBAL = симлинк на другое -> ln -sfn "$LOCAL" "$GLOBAL". В отчете укажи, куда указывал раньше.
- GLOBAL = пустая папка -> rmdir "$GLOBAL"; ln -s "$LOCAL" "$GLOBAL".
- GLOBAL = папка с файлами -> КОЛЛИЗИЯ. Не действуй. В плане предложи варианты:
  (а) перенести новые из GLOBAL в LOCAL через `rsync -av --ignore-existing "$GLOBAL"/ "$LOCAL"/`, потом заменить симлинком;
  (б) переименовать GLOBAL в `memory.bak.<дата>`, симлинк создать заново.
  Покажи `diff` для совпадающих имен.
- GLOBAL отсутствует, родитель есть -> ln -s "$LOCAL" "$GLOBAL".
- GLOBAL отсутствует, родителя нет -> mkdir -p "$(dirname "$GLOBAL")"; ln -s "$LOCAL" "$GLOBAL".
- GLOBAL = не папка/не симлинк (например, обычный файл) -> стоп, сообщи.

ШАГ 3. Покажи план и жди "ок".

Структура плана:
- Текущее состояние LOCAL и GLOBAL (по одной строке каждое).
- Намеченные действия списком, по пунктам, с буквальными командами.
- Будет ли создан/изменен MEMORY.md и feedback_local_paths.md.
- Что НЕ трону.
- Блокеры/вопросы.

Жди явного "ок", "go", "делай" или эквивалента. Без подтверждения - не действуй.

ШАГ 4. Действуй (только после "ок").

Выполни выбранный кейс из ШАГ 2.

ШАГ 5. Тест целостности симлинка.

- printf "probe" > "$LOCAL/_probe.md"
- diff <(printf "probe") <(cat "$GLOBAL/_probe.md") должен быть пустым
- rm "$LOCAL/_probe.md"

Если тест упал - выполни откат (ШАГ 9) и сообщи.

ШАГ 6. Запиши правило про локальные пути файлов в память.

Если файла "$LOCAL/feedback_local_paths.md" еще нет - создай его с таким содержимым:

---
name: Локальные пути файлов
description: В этом проекте использовать пути от корня проекта, не абсолютные глобальные
type: feedback
---

В этом проекте всегда указывай пути относительно корня проекта (`docs/foo.md`, `app/Models/User.php`), не абсолютные с домашней директории или с сервера (`/Users/<user>/...`, `/var/www/...`).

**Why:** проект синкается между устройствами и/или общий с другими разработчиками. Абсолютные пути не переносятся: в памяти, в комментариях, в коммитах глобальный путь становится мусором при смене устройства или при работе другого человека.

**How to apply:** в ответах в чате, в записях в памяти, в git-коммитах, в комментариях кода, в документации - пути от корня проекта. Абсолютные пути допустимы только когда они реально внешние и не переносятся (`/etc/cron.d/...`, `/opt/php85/...`, артефакты деплоя на сервере).

---

После создания файла - добавь строку в "$LOCAL/MEMORY.md" (если такой строки еще нет):
- [Локальные пути файлов](feedback_local_paths.md) - пути от корня проекта, не глобальные

ШАГ 7. Создай правило типографики для русских текстов.

Если файла ".claude/rules/typography-ru.md" еще нет - создай папку `.claude/rules/` (если ее нет) и сам файл. Содержимое получи из канона:

- По HTTP: WebFetch `<canon_base>/rules/typography-ru.md` -> запиши в проект.
- Локально: `cp <canon_base>/rules/typography-ru.md .claude/rules/typography-ru.md`.

`canon_base` берется как директория на уровень выше этого файла (см. КОНТЕКСТ ЦЕПОЧКИ).

Это правило универсально и не зависит от типа проекта (кодинг/управление/учеба/документация/claude-tooling), поэтому создается на этом шаге, до основного scaffold. В CLAUDE.md его подключит шаг 02 ссылкой `@.claude/rules/typography-ru.md`.

Если файл уже существует - НЕ перезаписывай. Прочти его содержимое и проверь, нет ли там маркеров старой формулировки правила про тире:

- фраза "только короткое" (про тире);
- "en-dash" в роли предписания (а не контрпримера в backticks);
- "короткое тире" / "короткий дефис" в роли предписания.

Если такие маркеры есть, проект был развернут со старой версией этого промта. В ШАГ 10 явно отметь: "обнаружена старая формулировка правила типографики - после bootstrap-цепочки запусти `sync` (он подтянет свежий `typography-ru.md` из канона)". Сам sync отсюда не запускай - он требует `.claude/canon.yaml`, который создается в bootstrap-02.

ШАГ 8. .gitignore.

Память в этом репозитории коммитим обязательно (история памяти полезна, привязка к проекту прозрачнее). Поэтому:

- Убедись, что `.claude/memory/` НЕ в .gitignore. Если оно там - покажи мне строку и спроси, удалять ли (фикс делаешь только после моего "ок").
- Дополнительно: проверь, что `.claude/settings.local.json` В .gitignore (это локальные пользовательские настройки, не должны коммититься). Если нет - добавь после моего "ок".

ШАГ 9. Откат (только если тест упал).

- Если симлинк создан, но тест целостности упал и `[ -L "$GLOBAL" ]` = true -> `rm "$GLOBAL"`.
- НЕ удаляй $GLOBAL, если это обычная папка/файл. Сообщи.

ШАГ 10. Отчет.

Структура:
- Исходное состояние LOCAL и GLOBAL.
- Какие действия выполнил (или "ничего не понадобилось").
- Итоговое состояние.
- Тест целостности: passed / failed.
- Создан ли feedback_local_paths.md.
- Состояние .claude/rules/typography-ru.md: создан / уже существовал и актуален / уже существовал с устаревшей формулировкой (после bootstrap-цепочки рекомендуется запустить sync).
- Состояние .gitignore (memory не игнорится, settings.local.json игнорится).

ШАГ 11. Цепочка - запуск bootstrap-02-scaffold.

После отчета (ШАГ 10) спроси одной строкой: "Запустить bootstrap-02-scaffold.prompt.md? (да/нет)".

Если ответ отрицательный - остановись, ничего не делай.

Если ответ утвердительный (да/go/делай/+):

- Следующий файл - сиблинг в той же папке: `<dirname(этого файла)>/bootstrap-02-scaffold.prompt.md`. По HTTP - WebFetch, локально - Read.
- Содержимое файла - это инструкции для тебя. Выполни их как прямое продолжение текущей сессии (не пересылай пользователю, не цитируй - именно выполни). Все правила безопасности из 02 действуют.
- Когда 02 закончит свою работу - он сам инициирует шаг цепочки, ведущий к 03.

ПРАВИЛА БЕЗОПАСНОСТИ.

- Никаких `rm -rf` ни при каких условиях.
- Без моего "ок" после плана - никаких изменений.
- Не трогай ничего, кроме GLOBAL, LOCAL, .claude/rules/typography-ru.md и (по моему явному "ок") .gitignore.
- При коллизии (папка с файлами в GLOBAL) - остановись и спроси.

---

После того как агент отчитается "все ок" (или "уже настроено") - можно запускать `bootstrap-02-scaffold.prompt.md`, а потом один из:

- `bootstrap-03-coding.prompt.md` - кодовые проекты
- `bootstrap-03-management.prompt.md` - управленческие
- `bootstrap-03-education.prompt.md` - учебные
- `bootstrap-03-documentation.prompt.md` - документация (мануалы, технические тексты)
- `bootstrap-03-claude-tooling.prompt.md` - проекты-конструкторы для Claude (промты, агенты, канон)

Отдельно: если в отчете обнаружена устаревшая формулировка правила типографики (ШАГ 7 и ШАГ 10), после bootstrap-цепочки запусти `sync` - он подтянет свежий `typography-ru.md` из канона. Накопленные в проекте тексты с `–`/`—` (если есть) sync не чистит - правь точечно при следующих обращениях к этим файлам.
