Синхронизируй текущий проект с каноном claude-toolkit.

0. До выбора ref и любых HTTP-загрузок проверь `.ai-bootstrap/sync.json`, `.ai-bootstrap/migration.json` и `.ai-bootstrap/journal.json` в корне проекта, включая ссылки и битые ссылки. Несколько журналов - отказ без выбора, удаления или recover.
   - При sync journal сразу используй сохраненную вне клиента закрепленную `migrations/ai-sync.prompt.md` и immutable пару `ai-sync.py`/`ai-bootstrap.py` прерванной операции: check, согласованное recover, check. Не требуй установленного `canon-sync`, не разрешай main/ref, не загружай skill или source package. При неизвестной provenance или недоступной подтвержденной паре остановись с диагностикой; не подставляй latest main. После recovery заверши router.
   - При migration journal направь к закрепленной процедуре `migrations/ai-layout.prompt.md` прерванной операции и только `ai-migrate.py check/recover --root ROOT`; при bootstrap journal - к `bootstrap/bootstrap-ai.prompt.md` и только `ai-bootstrap.py check/recover --root ROOT`. Чужой recover не запускай; новое обновление/ref discovery при pending journal не выполняй. Если закрепленный recovery маршрут недоступен, остановись без выбора нового main.
   - Только без журналов проверь `.AI` и `.ai-bootstrap`, включая файлы и симлинки (в том числе битые). Если любой путь существует, используй общий навык `canon-sync` (`.AI/skills/canon-sync/SKILL.md`) и его отдельную pinned процедуру `migrations/ai-sync.prompt.md`, затем заверши router. Если установленного навыка еще нет, получи его точными байтами по HTTP: HTTPS `source.base` из `.AI/canon/canon.state.json`, иначе продуктовый default `https://raw.githubusercontent.com/dewil/claude-toolkit/main`; из сохраненного URL выводи репозиторий, ref обновления по умолчанию `main` (явный выбор пользователя соблюдай), разреши его в полный commit SHA и читай навык из того SHA, передав навыку этот SHA и PINNED_URL как уже зафиксированную версию операции; повторно main не разрешай. Локальный клон не ищи. Поврежденный AI-layout дает отказ; к legacy не переходи.
   - Если `.AI` и `.ai-bootstrap` отсутствуют, проверь маркер legacy-подключения `.claude/canon.yaml`. При его наличии сообщи, что legacy sync больше не поддерживается и для перехода в `.AI` пользователь должен отдельно запросить миграцию через `migrations/ai-layout.prompt.md`; остановись. Не запускай legacy sync и не начинай миграцию автоматически.
   - Если нет ни `.AI`/`.ai-bootstrap`, ни legacy-маркера, синхронизировать нечего. Для нового клиента направь к bootstrap через `start.md` и остановись; автоматически bootstrap не запускай.

Миграция legacy в `.AI` - только по отдельному явному запросу через `migrations/ai-layout.prompt.md`; `/canon` ее не запускает.
