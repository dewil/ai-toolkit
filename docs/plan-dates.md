# plan-dates: механика плана работ

Скрипт `scripts/plan-dates.py` берет на себя ручную часть плана работ по ранбуку плана (пересчет таблицы держателей, чистка "Готово за сутки", проверка формы). Расчет дат прогноза по графу этапов в эту версию не входит.

Спека v1 (ведущий ALP AI, 23.11, по итогам обкатки формата плана 20-22.11 - решение dwl: вариант Б).

## Вызов

```
python3 scripts/plan-dates.py <команда> --plan <plan.md> --data <проект-sroki.json> [--now ISO8601] [--write]
```

- Команды: `recalc`, `prune`, `lint`, `all` (`recalc`, затем `prune`, затем `lint`).
- `--now` - текущее время для расчетов (ISO8601 с поясом); по умолчанию сейчас. Пояс вывода и разбора дат плана - Europe/Moscow.
- Без `--write` файл плана не меняется: печатается, что было бы изменено. С `--write` изменения `recalc`/`prune` записываются атомарно (временный файл и переименование), остальное содержимое плана сохраняется побайтно.
- Коды выхода: 0 - нет ошибок проверки; 1 - есть ошибки проверки (`lint`, `all`); 2 - ошибка вызова или данных (нет файла, битый JSON, нет обязательного раздела). Строки результата: `ERROR: <текст>` и `WARN: <текст>` в stdout, по одной на находку.

## Данные (`<проект>-sroki.json`)

Используемые поля (остальные игнорируются):

```json
{
  "holders": {
    "root": {"label": "root (ревью и выкатка)", "default": [1, 4],
             "samples": [{"what": "PR #46", "asked": "2026-11-20T18:20+03:00", "answered": "2026-11-22T11:28+03:00"}]}
  },
  "open_waits": [{"id": "pr47", "holder": "root", "since": "2026-11-22T17:05+03:00", "where": "PR #47"}]
}
```

- `label` - имя в таблице; без него - ключ держателя.
- `default` - [обычно, затяжно] в днях для случая "мало данных"; без поля - [1, 3].
- Время без пояса читается как Europe/Moscow.

## recalc: таблица "Держатели"

- Длительность ожидания = answered - asked в календарных днях.
- Замеров = число закрытых samples (есть asked и answered, answered >= asked).
- Если замеров 5 и больше: обычно = медиана длительностей; затяжно = второе по величине значение среди последних 10 закрытых (по answered). Значения выводятся целыми днями с округлением вверх, но не меньше 1.
- Если замеров меньше 5: обычно и затяжно - из `default`, в ячейке "Замеров, шт" - `N (по умолчанию: мало данных)`.
- Открыто = число элементов `open_waits` этого держателя.
- Порядок строк - порядок ключей в `holders`.
- Перезаписывается первая markdown-таблица в разделе `## Держатели` с колонками `| Держатель | Обычно, дн | Затяжно, дн | Замеров, шт | Открыто, шт |`; текст раздела до и после таблицы не меняется. Нет раздела - код 2.

## prune: "Готово за сутки"

- Раздел `## Готово за сутки`: элементы списка `- ...`.
- Время элемента - первая отметка `ДД.ММ ЧЧ:ММ` сразу после `- ` или последняя отметка `ДД.ММ ЧЧ:ММ` в круглых скобках в конце строки. Год - текущий; если дата получается позже `now` больше чем на сутки - прошлый год.
- Элемент старше 24 часов относительно `now` удаляется (вместе со строками продолжения, начинающимися с отступа). Элемент без читаемого времени остается (его отметит `lint`).

## lint: проверка формы

Планы без раздела вопросов совместимы с прежним форматом. Если вопросы открыты, перед блокировками идет один раздел `## Вопросы к владельцу - N` с уникальными заголовками `### Qn. Текст`. Номера положительные, пропуски допустимы. Ноль означает отсутствие раздела. Одна строка блокировок перечисляет те же номера в колонке "Что" (`Вопросы Q1, Q3`). Держатель - "Владелец плана" или имя владельца из данных (ключ owner либо первый держатель по конвенции плана, его ключ или label). Запись про вопросы в шапке оформляет ведущий.

Ошибки (`ERROR`, код 1):
- заголовок раздела вопросов, его положение, число или уникальность вопросов нарушают этот формат; при открытых вопросах отсутствует единая согласованная строка владельца;
- нет ровно одной строки `Обновлено: ДД.ММ ЧЧ:ММ MSK.` в шапке (до первого `## `);
- строка таблицы с другим числом колонок, чем заголовок;
- дубль строки внутри одной таблицы;
- в таблице раздела `## Блокировки - кого ждем - N` пустая колонка "Снимется" или "Где" (кроме строки, где в колонке "Что" есть `ничего не ждем`);
- в таблице раздела `## В работе сейчас - N` пустая колонка "Готово";
- число N в заголовках `## Блокировки - кого ждем - N` (без строк `ничего не ждем`), `## В работе сейчас - N`, `## Риски - N` не равно числу строк таблицы раздела;
- элемент "Готово за сутки" без читаемого времени.

Предупреждения (`WARN`):
- отметка "Обновлено" старше 24 часов;
- элемент "Готово за сутки" старше 24 часов;
- открытое ожидание висит дольше нормы "затяжно" своего держателя (по данным) - `горит`;
- строк в таблице рисков больше 7;
- в шапке (между заголовком `# ` и первым `## `) больше 5 непустых строк.

## Уточнения (ведущий, 23.11, по вопросам автора тестов)

1. Медиана - по всем закрытым замерам держателя; при четном числе - среднее двух средних значений, затем округление вверх и минимум 1. Окно последних 10 - только для "затяжно".
2. При 5 и больше замерах ячейка "Замеров, шт" - просто число.
3. Если у элемента "Готово" есть и отметка в начале, и отметка в скобках в конце, действует отметка в начале.
4. "Старше 24 часов" - строго больше 24 часов; ровно 24 часа - не старше (для prune и для предупреждений lint).
5. "Горит" - сырой возраст ожидания в днях строго больше нормы "затяжно" (целое значение из таблицы держателя после правил recalc). Текст предупреждения содержит слово `горит` и `id` ожидания.
6. Ноль или две и больше строки "Обновлено" в шапке - одинаково ERROR. Строка "Обновлено" входит в число непустых строк шапки.
7. `all` без `--write`: lint проверяет результат recalc и prune в памяти.
8. Отсутствие раздела `## Держатели` - код 2 только для `recalc` и `all`; `prune` и `lint` без него работают.
9. `--data` обязателен для всех команд; нет файла или битый JSON - код 2.
10. `all --write`: результат recalc и prune записывается, даже если lint нашел ошибки; код выхода 1.
11. Нет прав на запись в каталог плана - код 2, исходный файл цел.
12. Держатель из `open_waits`, которого нет в `holders`: recalc его не показывает; lint дает WARN с `id` ожидания.
13. Отметка времени элемента в круглых скобках считается стоящей в конце строки, если после закрывающей скобки идут только пробелы и точка (шаблон ранбука: `(...; ДД.ММ ЧЧ:ММ).`). Это касается `prune` и `lint`. Уточнение по сверке 23.11: на плане по ранбуку отметки с точкой не распознавались.
