# Однократный переход на новые навыки

Имена `review`, `implement`, `proofread` заменяют прежние `codex-audit`, `codex-implement`, `technical-document-editing`. Старые входы и алиасы в новом каноне отсутствуют. Исторические отчеты и receipts не переписываются. Профили Codex, роли и подкоманды сохраняют имена.

Новая установка получает только актуальные навыки. Существующий клиент требует отдельного согласованного перехода: обычный sync сохраняет removed-upstream и сам старые источники не удаляет. Этот документ не разрешает обновлять клиент или останавливать процессы. Владелец останавливает рабочие сессии перед переходом.

## До применения

1. Прочитай pinned процедуру [AI sync](../migrations/ai-sync.prompt.md), проверь журналы и сохрани оба инструмента одного SHA до healthy check.
2. Получи согласие на конкретный клиент и состав изменений. Прочитай intent/state, все локальные дополнения и ссылки на снимаемые навыки. MODELS должен содержать актуальные имена в применимых строках; проверь отсутствие codex-audit, codex-implement и technical-document-editing именно в действующих назначениях (историческая справка допустима); обновление таблицы само по себе не устанавливает навыки. Не редактируй чужие назначения без поручения.
3. Сохрани отдельную резервную копию конфигурации/intent/state и изменяемых источников по процедуре проекта. Автоматический архив retire сохраняет только снимаемые чистые источники, не весь клиент.
4. Если снимаемый файл изменен локально, находится в overrides, skip_sync или local_only, retire откажет. Сначала отдельно разбери дополнения, перенеси принятый смысл в новые владельцы и согласуй снятие исключения. Не подменяй hash базы в state и не возвращай файл к базе до проверенного сохранения дополнений. При неизвестной принадлежности остановись.
5. Обнови действующие проектные ссылки отдельной согласованной правкой. Изменение локальных заметок не входит в механический retire. Не правь generated AGENTS/CLAUDE/START вручную.

## Plan, apply, check

Используй только пути, которые реально tracked у этого клиента и снимаются выбранной поставкой; coding-навыка implement может не быть в клиентах других типов. Значения ниже - пример для клиента со всеми тремя старыми навыками. `ROOT`, `PINNED_URL` и инструменты подставь из pinned процедуры:

```bash
python3 /tmp/ai-sync/ai-sync.py plan --root "$ROOT" --source-base "$PINNED_URL" \
  --retire-source skills/codex-audit/SKILL.md \
  --retire-source skills/codex-implement/SKILL.md \
  --retire-source skills/technical-document-editing/SKILL.md
```

Покажи новые файлы, каждый снимаемый путь, сохраняемые исключения и backup. После разрешения передай тот же источник, список и digest:

```bash
python3 /tmp/ai-sync/ai-sync.py apply --root "$ROOT" --source-base "$PINNED_URL" \
  --expect-plan "$PLAN_SHA256" \
  --retire-source skills/codex-audit/SKILL.md \
  --retire-source skills/codex-implement/SKILL.md \
  --retire-source skills/technical-document-editing/SKILL.md
python3 /tmp/ai-sync/ai-sync.py check --root "$ROOT"
```

`--retire-source` применим только к plan/apply и только к точным skill-файлам. Файл должен отсутствовать в выбранном upstream, совпадать с tracked базой и не иметь локального исключения. Неизвестный путь, дубли, unsafe path, symlink, измененный файл или конфликт backup дают отказ. Флаги входят в digest; менять список после plan нельзя.

Архив: `.ai-bootstrap/retired/<SHA256 содержимого>/<canonical-path>`. Он записывается до снятия файла, state фиксируется последним. Снятие исключает источник из source_files, START и производных входов; история остается в `state.sync.retired_sources`. Повтор при неизменном архиве и отсутствующем снятом файле безопасен. Пустые каталоги могут остаться: без SKILL.md они не являются навыками; неизвестные соседние файлы не удаляются.

## Прерывание и приемка

Операция со снятием использует sync journal schema 2; обычный sync остается schema 1. Используй только сохраненную пару инструментов, которая создала журнал. Recovery работает offline по журналу; не запускай новый main и не удаляй журнал. Перед продолжением - check, затем согласованный recover и check по pinned процедуре. Дрейф архива, удаляемого файла или защищенных входов требует разбора, не force.

После check проверь отсутствие старых SKILL.md, сохранность project_id, памяти, настроек и дополнений. Открой новую сессию нужного адаптера: новые навыки, чтение MODELS и продолжение файловой задачи. Непроверенные адаптеры отметь NOTRUN. Только после этой приемки возобновляются рабочие сессии.

Архив помогает ручному восстановлению, но не является автоматическим rollback. Не возвращай отдельный старый файл при новом state. Для отката останови агенты и восстанови согласованный целостный снимок средствами проекта, затем build/check соответствующей pinned парой. При отсутствии полного снимка не обещай восстановление одним флагом.
