Файл-инструкция для проектов, подключенных к канону claude-toolkit. Открой Claude Code в **корне проекта** и попроси выполнить этот файл (например: `выполни инструкции из <путь>/migrations/readme-manifest.prompt.md`).

Когда применять: проект bootstrap'нут от claude-toolkit раньше, чем появился паттерн "README.md - человеческий манифест, CLAUDE.md - агентский контекст". Промт заводит в проекте `README.md` (человеческий манифест), переносит в него человеческое описание из `CLAUDE.md`, оставляет в `CLAUDE.md` только агентское + `@README.md`. Одноразовый, **идемпотентный**: если разделение уже сделано - отрабатывает как no-op.

**ВАЖНО.** Никаких правок до явного "ок". Сначала аудит, потом план, потом действие. Перенос человеческого текста - операция с суждением (что человеческое, что агентское); показывай план построчно и жди подтверждения. Если структура нестандартная (нет `CLAUDE.md`, нет `.claude/canon.yaml`) - остановись и спроси, а не "делай как умеешь".

# Задача: развести README.md (человеческий манифест) и CLAUDE.md (агентский контекст)

**Запускай из корня проекта.** Пути относительные.

## Контекст

Паттерн канона: `README.md` в корне - человеческий манифест проекта (зачем, как устроено, как работать; читают люди и GitHub). `CLAUDE.md` - агентский контекст (@-импорты правил, служебные заметки для Claude), который импортирует README строкой `@README.md`, так что человеческое описание попадает Claude в контекст без дублирования. Раньше человеческое описание нередко лежало прямо в `CLAUDE.md` (особенно у management-проектов из шаблона `management-CLAUDE.md` с разделами "О проекте", "Действующие лица", "Глоссарий" и т.д.). Этот промт приводит забутстрапленный проект к новому виду.

`README.md` - **шаблон**, он не отслеживается в `canon.yaml.files`. Поэтому `canon.yaml` этот промт НЕ трогает.

## ШАГ 1. Аудит (только чтение)

1. Прочитай `.claude/canon.yaml` -> возьми `canon.raw_base` (например, `https://raw.githubusercontent.com/dewil/claude-toolkit/main`). Если `canon.yaml` нет - проект не подключен к канону; сообщи и остановись.
2. Проверь наличие и содержимое:
   - `README.md` в корне проекта - есть ли, и если есть, что это. Три состояния, нормализуй их так:
     - **полноценный человеческий манифест** - считаем "README есть";
     - **заглушка-шаблон (только TODO, не заполнен)** - приравниваем к "README отсутствует" (шаблон безопасно перезапишет пустышку);
     - **технический README другого назначения** (например, README библиотеки с инструкцией по установке, не манифест проекта) - **не трогай его и остановись**: это нестандартный случай, спроси пользователя, вливать ли манифест в этот README или завести отдельный. Дальше по шагам не иди без ответа.
   - `CLAUDE.md` в корне - прочитай целиком. Раздели его содержимое на два вида:
     - **агентское**: @-импорты (`@.claude/rules/*`, `@project-structure.md`), инструкции для Claude, служебные заметки, правила регистрации;
     - **человеческое**: описание проекта (что это, зачем), действующие лица, глоссарий, устройство, процессы, ссылки на ресурсы - то, что адресовано людям.
   - Есть ли в `CLAUDE.md` строка `@README.md`.

Определи случай:

- **A. Разделение уже сделано.** `README.md` - человеческий манифест, в `CLAUDE.md` человеческого контента нет (только агентское) и есть `@README.md`. Чистый no-op: сообщи "README/CLAUDE уже разведены" и **выйди**.
- **E. Не хватает только импорта.** `README.md` - готовый человеческий манифест, в `CLAUDE.md` человеческого контента нет, но строки `@README.md` в `CLAUDE.md` нет. Тривиальный случай: только добавить `@README.md` в `CLAUDE.md`, ничего не переносить и не создавать.
- **B. Нет README, CLAUDE.md тонкий.** README в корне нет (или только заглушка), `CLAUDE.md` - в основном @-импорты, человеческого контента в нем мало или нет. Нужно: создать README из шаблона + добавить `@README.md` в CLAUDE.md.
- **C. Нет README, человеческое в CLAUDE.md.** README в корне нет, а `CLAUDE.md` содержит человеческие разделы (описание проекта, действующие лица и т.д.). Нужно: создать README, **перенести** человеческие разделы из CLAUDE.md в README, оставить в CLAUDE.md агентское + `@README.md`.
- **D. README есть и содержателен, но CLAUDE.md тоже несет человеческое.** Нужно: README не трогать (это уже манифест), перенести человеческое из CLAUDE.md в подходящие разделы README (по согласованию), добавить `@README.md` в CLAUDE.md, если его нет.

## ШАГ 2. План

Покажи определенный случай и что будешь делать. Случай A завершается на ШАГ 1 как no-op, а "технический README другого назначения" - остановкой с вопросом; сюда доходят B/C/D/E.

- **E:** только добавить `@README.md` в `CLAUDE.md`. Ничего не создавать и не переносить.
- **B:** создать `README.md` из шаблона канона (с TODO-заглушками); в `CLAUDE.md` добавить `@README.md`. Указать, что README дальше заполняется вручную.
- **C / D:** покажи **построчный план переноса** - какие разделы/абзацы `CLAUDE.md` ты считаешь человеческими и переносишь в README (в какие разделы), что остается в CLAUDE.md как агентское. Это операция с суждением - жди явного согласия с раскладкой, не переноси на глаз без подтверждения. Для случая C - README собирается из шаблона + перенесенный контент; для D - контент вливается в существующий README.

Для всех случаев (B/C/D), где `@README.md` в CLAUDE.md еще нет - покажи, что добавишь строку импорта.

`canon.yaml` не трогаю (README - шаблон, не отслеживается).

## ШАГ 3. Жди "ок"

Без явного "ок" / "делай" - ничего не меняй. Для C/D подтверждение должно касаться конкретной раскладки переноса из ШАГ 2.

## ШАГ 4. Действие (после "ок")

1. **Создай README (случаи B, C).** Если README в корне нет - получи шаблон точными байтами: `curl -fsSL <raw_base>/templates/README.md` -> запиши в `README.md`. (Если `curl` недоступен - фолбэк `WebFetch` того же URL.) Существующий содержательный README (случай D) не перезаписывай.
2. **Перенеси человеческое (случаи C, D).** Согласованные в ШАГ 2 разделы из `CLAUDE.md` перенеси в `README.md` (в случае C - на место соответствующих TODO-заглушек шаблона; в случае D - в подходящие разделы существующего README). Переносишь текст как есть, без пересказа; правь только заголовки под структуру README.
3. **Почисти CLAUDE.md (случаи C, D).** Удали из `CLAUDE.md` перенесенные человеческие разделы. Оставь агентское: @-импорты правил, `@project-structure.md`, служебные инструкции.
4. **Добавь импорт.** Если в `CLAUDE.md` нет `@README.md` - добавь строку (человеческий манифест логично импортировать в начале, до @-импортов правил или рядом с `@project-structure.md`).
5. `canon.yaml` не трогай.

## ШАГ 5. Проверка

- `README.md` есть в корне и содержит человеческий манифест (не только TODO, если был перенос).
- В `CLAUDE.md` нет продублированного человеческого описания - только агентское.
- Для случаев C/D: каждый перенесенный раздел есть **ровно в одном** файле - в README, и его **больше нет** в `CLAUDE.md` (частая ошибка - copy без delete: текст остался в обоих). Пройди по перенесенным разделам поименно и убедись.
- В `CLAUDE.md` есть строка `@README.md`.
- `canon.yaml` не изменен.

## ШАГ 6. Отчет

Кратко: какой был случай, создан ли README из шаблона, какие разделы перенесены из CLAUDE.md, что осталось заполнить вручную (TODO-заглушки README).

## Правила безопасности

- Никаких правок до "ок"; для переноса человеческого текста (C/D) - подтверждение конкретной раскладки.
- Трогаешь только `README.md` и `CLAUDE.md` в корне. Больше ничего.
- Содержательный существующий `README.md` не перезаписываешь.
- `canon.yaml` не правится (README - шаблон, не отслеживается в `files`).
- Никаких `rm -rf`.
