# Архитектура канона

Канон хранит повторяемые приемы работы; проект владеет своими решениями, задачами и памятью. Переносимый источник знаний в новом клиенте - `.AI/`. Вендор задает способ подключения и доступные инструменты, а не место хранения знаний.

## Выбор компонента

| Компонент | Когда нужен | Где источник |
| --- | --- | --- |
| Правило | Норма поведения, применимая к типу проекта | `rules/` |
| Навык | Процедура по определенному запросу | `skills/<имя>/SKILL.md` |
| Роль | Изолированный исполнитель с явным брифом и границами | `agents/` |
| Скрипт | Детерминированная механика, проверяемая запуском | `scripts/` |
| Команда | Тонкий вход среды к уже существующей процедуре | `commands/` |
| Шаблон | Начальный документ, которым после копирования владеет проект | `templates/` |

Сначала используй существующий компонент. Новая абстракция нужна под повторяемые реальные случаи, с названной стоимостью сопровождения. Одно правило не дублируется в командах и навыках: они направляют к источнику. `manifest.yaml` - единственный реестр раскатываемых компонентов и их типов. Репозиторные тесты, CI, `run-tests.py` и документация сопровождения в этот реестр не входят.

## Владение и подключение

В новом клиенте точные байты канона сохраняются в `.AI/rules`, `.AI/skills`, `.AI/roles`, `.AI/commands`; скрипты - в `scripts/`. Проектные решения находятся в редактируемом `.AI/project.md`; память - в `.AI/memory`; задачи - в проектном бэклоге, по умолчанию `docs/backlog/`, завершенные - в `docs/done/`.

`AGENTS.md` и `CLAUDE.md` - производные входы. Их собирает `ai-bootstrap.py build` по источникам и политике контекста; ручная правка результата блокирует сборку. START направляет к остальным знаниям. `.claude/` и `.agents/skills` предоставляют совместимые ссылки; нативные настройки, секреты и разрешения не копируются. Frontmatter ролей остается конфигурацией Claude; другие среды читают общие инструкции роли и используют свои проверенные возможности.

Личная память этого публичного проекта хранится вне репозитория. Bootstrap также проверяет приватные назначения перед записью в клиентский Git. Общая файловая память - источник для передачи между агентами; глобальный векторный поиск требует отдельного подключения.

## Жизненный цикл

- **Новый клиент:** `start.md` → `.AI` bootstrap → план → применение → check и проверка новой сессией.
- **Существующий legacy:** свой `/canon` или legacy-движок. Отдельный явно запрошенный переход в `.AI` - навык migrate и транзакционный `ai-migrate.py`, с архивом и recover.
- **Обновление `.AI`:** общий навык `canon-sync` и `/canon` направляют к pinned процедуре `ai-sync` и детерминированному `ai-sync.py`: read-only plan, согласованное digest-bound apply, check/recover. [Эксплуатация](docs/ai-sync.md). Legacy sync отказывает на новой раскладке; build пересобирает установленные источники без загрузки новой версии.
- **Изменение канона:** [SDD-процедура](docs/sdd.md), независимые тесты/критерии до реализации, другая модель для сверки, полный CI и документы вместе с изменением. Деплой - по разрешениям владельца.

Состояние нового клиента - `.AI/canon/canon.state.json`; идентичность - `.AI/project.json`. Машинное состояние меняют соответствующие инструменты, не агент вручную. Bootstrap, миграция и AI sync имеют общий exclusive lock и отдельные проверяемые журналы восстановления. Sync сохраняет истинные per-file базы и исключения, строит START и generated входы из effective corpus; policy принадлежит проекту. Несколько журналов одновременно блокируют работу; recover выполняет только владелец журнала. Legacy-релиз идентифицируется ревизией тега, descriptor строится из его Git-дерева и проверяется release CI.

## Границы поддержки

Первый исполняемый контракт - Linux, Python 3.11+. Codex-адаптер использует Linux bwrap и собственные профили. SDD допускает проверенную другую среду или передачу брифа в отдельную сессию; одинаковая или неизвестная модель не считается независимой сверкой.

Протокол и `.AI` не сертифицируют автоматически поведение четырех CLI. macOS/Windows не прошли приемку; DeepSeek требует выбранной оболочки. Подключение векторной индексации и массовая миграция - отдельные работы. Их отсутствие явно указано, а завершение SDD не закрывает эти задачи.
