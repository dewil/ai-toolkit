# Модель для задания

Перед каждой новой задачей, делегированием и продолжением работы заново прочитай общий файл MODELS. Это позволяет владельцу менять актуальные назначения без обновления канона. Не используй копию таблицы из памяти или предыдущего хода. Действующий вызов не прерывай: новое назначение применяется к следующему запуску.

## Источник и приоритет

Указатель - `AI_MODELS_FILE`, иначе файл, явно названный владельцем или пользовательской конфигурацией вне генерируемого корпуса клиента. Не ищи файл обходом соседних проектов. Путь, секреты, имена клиентов и личные назначения не входят в публичный канон. Наличие `local_only` не делает содержимое приватным или скрытым от контекста.

1. Найди строку текущего проекта, роли, навыка и условия; при ее отсутствии - подходящую общую строку.
2. Возьми текущие модель, effort и сервер этой строки. Значение «Канон» в пользовательской таблице служит сравнением, не перекрывает колонку «Сейчас».
3. Если указателя, файла или подходящей строки нет - используй дефолт ниже и отметь `fallback`. Нечитаемый файл: сообщи причину и используй канонический fallback по этому контракту. Не выдавай отказ доступа за пустую таблицу.
4. Битая или неоднозначная таблица, противоречивые совпадения, устаревшее имя навыка в применимой строке - диагностика и остановка зависимого запуска. Недоступная назначенная модель, сервер или неподдерживаемый effort - не отсутствие строки и не разрешение fallback.

Jev дает advisory-оценку сложности и не переопределяет назначение MODELS. Запрос сменить текущие назначения выполняется только по поручению владельца, с ревизией и областью; канонические дефолты сохраняются. Открытые сессии не объявляются переключенными без readback.

## Канонические дефолты

Эти значения используются без подходящего назначения MODELS. Сервер по умолчанию - текущая разрешенная среда, если выбранный адаптер в ней проверен; иначе диагностика. Главную модель приложения это правило автоматически не переключает. Для исполнения текущим агентом фиксируй фактическую модель приложения; таблица задает новые делегированные запуски. Невозможность исполнить обязательное назначение не обходи самостоятельным запуском другой модели.

| Роль / процедура | Модель | Effort |
| --- | --- | --- |
| architect, planner / requirements | claude-opus-5-5 | medium |
| implementer / этап SDD | claude-sonnet-5-5 | high |
| implement / проверенный Codex writer | gpt-6-astra | medium |
| review / Codex audit, second-opinion, advocate, adversarial, compliance | gpt-6.1-sol | medium |
| review / необратимый эффект или escalation | gpt-6.1-sol | high |
| review / отдельно разрешенный Claude reviewer | claude-opus-5-5 | medium; high при необратимом эффекте |
| test-writer, code-reviewer, copy-editor | claude-sonnet-5-5 | medium |
| note-taker, note-writer, summarizer / proofread | claude-sonnet-5-5 | medium |
| debugger, tracker | claude-sonnet-5-5 | low |
| explorer, searcher, librarian | claude-haiku-5-5 | low |

SDD использует роль соответствующего этапа. Для остальных навыков выбирай роль фактической работы: поиск/инвентаризация - searcher/explorer/librarian; требования и планирование - planner; подготовка текста - note-writer/summarizer; проверка - code-reviewer/copy-editor; изменение кода - implementer; диагностика - debugger. Скрипты конвертации, синхронизации и подсчета не требуют нового вызова модели только из-за наличия навыка. Специализированные llm-ru и jev-decide сохраняют ограничения провайдера, данных и разрешенных моделей; несовместимое назначение дает конфликт, не передачу данных другому провайдеру.

## Запуск и проверка

Перед запуском зафиксируй ревизию MODELS и выбранную строку либо canonical fallback, requested модель/effort/сервер. Разреши алиас в точную модель до запуска. Адаптер обязан уметь применить назначение; native frontmatter роли не разрешает игнорировать MODELS. Если это невозможно, сохрани блокер, не ослабляй permissions и не меняй глобальные настройки.

Передай выбранную модель и effort явно. Машинный профиль сохраняет настройки транспорта/доступа, но его поле model не подменяет выбор из MODELS или канона. Для Codex используй рецепт review/codex.md. При resume перечитай таблицу; если назначение изменилось, нужен новый контекст с handoff, поскольку продолжение наследует прежние модель/effort. Ограничения независимого SDD-compliance сохраняются.

Сохрани actual модель и effort по metadata запуска; неподтвержденное - `unknown`. Запрошенный флаг не является доказательством фактического effort. Для независимой проверки выбранные модели автора/проверяющего должны различаться до запуска, а actual проверяется после. Профили с разными именами и разные сессии одной модели не обеспечивают независимость. При неизвестной actual-модели приемку не объявляй PASS.
