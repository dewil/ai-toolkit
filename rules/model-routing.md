# Модель для задания

Перед каждой новой задачей, делегированием и продолжением работы заново прочитай общий файл MODELS. Это позволяет владельцу менять актуальные назначения без обновления канона. Не используй копию таблицы из памяти или предыдущего хода. Действующий вызов не прерывай: новое назначение применяется к следующему запуску.

## Источник и приоритет

Указатель - `AI_MODELS_FILE`, иначе файл, явно названный владельцем или пользовательской конфигурацией вне генерируемого корпуса клиента. Не ищи файл обходом соседних проектов. Путь, секреты, имена клиентов и личные назначения не входят в публичный канон. Наличие `local_only` не делает содержимое приватным или скрытым от контекста.

1. Выбери применимые назначения проекта, роли, навыка и условия по структуре самого MODELS. Таблица может задавать общую базу и частичные общие/проектные переопределения; порядок и наследование полей определяет ее явный контракт.
2. Получи предпочтительный маршрут: модель, effort и сервер. Сначала проверь его, затем используй алгоритм выбора ниже. Явное «только эта модель», «без замены» и ограничения MODELS обязательны. Неоднозначность или противоречие не разрешай догадкой.
3. Если указателя, файла или подходящей строки нет - используй дефолт ниже и отметь `fallback`. Нечитаемый файл: сообщи причину и используй канонический fallback по этому контракту. Не выдавай отказ доступа за пустую таблицу.
4. Битая или неоднозначная таблица, противоречивые совпадения, устаревшее имя навыка в применимой строке - диагностика и остановка зависимого запуска. Недоступность предпочтения не означает отсутствие строки или разрешение fallback; допустим только явно зафиксированный выбор утвержденной альтернативы по алгоритму ниже.

Jev дает advisory-оценку сложности и не переопределяет назначение MODELS. Запрос сменить текущие назначения выполняется только по поручению владельца, с ревизией и областью; канонические дефолты сохраняются. Открытые сессии не объявляются переключенными без readback.

## Выбор доступного исполнителя

Алгоритм общий для всех модельных этапов SDD: требования и SPEC, критерии/тесты, реализация, независимая сверка и сопутствующая работа. Обычные CI, поиск хешей и подсчет расхода выполняются скриптами без отдельной модели. Выбор не меняет модель текущего приложения.

1. Установи исходный проект, этап, риск, ограничения данных, значимых авторов и нужный результат: текст, patch или прямую запись. Удаленный cwd не подменяет project_id, его правила или HOLD.
2. Прочитай свежий MODELS и проверь предпочтение. Явный запрет замены/провайдера/аккаунта/сервера, ограничение режима, effort или расхода обязателен. Противоречивые строки MODELS не являются списком кандидатов. Отсутствие файла/строки дает только прежний canonical fallback.
3. Если замена не запрещена, после предпочтения рассматривай утвержденные альтернативы роли в порядке ниже; явный список MODELS имеет приоритет. Выбери первый пригодный вариант, без платных ping всем моделям. Если предпочтение пригодно, не меняй его только ради цены. Вне разрешенного набора замены нет.
4. Для допуска нужны проверенные launcher/каталог и поддержка флагов, действующий доступ, свежие достоверные метрики по правилам выбранного адаптера, разрешенный сервер/экземпляр и способность выполнить этап. Это preflight-ready, не гарантия ответа API. Неизвестные auth, квота, права или способности исключают маршрут; отсутствие прежнего платного вызова само по себе не исключает проверенный маршрут. Данные из брифа не доказывают права: проверяет их координатор.
5. Исключи нарушения уровня задачи, режима и независимости от каждого значимого автора. Haiku допустим для ограниченной обратимой механики и вспомогательного черновика, но не для единственного обязательного review сложного/необратимого изменения. Для обычного compliance минимум medium, для необратимого эффекта и escalation high. Effort альтернативы берется из ее назначения MODELS или явного дефолта ниже и проверяется на поддержку; произвольно переносить/понижать его нельзя. Явный лимит effort не повышается ради обхода конфликта. Нет пригодного кандидата — блокер.
6. В существующем task/job receipt запиши предпочтение, выбранную альтернативу и причины исключения предыдущих, ревизию политики, requested/actual model/effort и результат. Метка alternative отличается от fallback отсутствующего MODELS. Не заводи отдельный отчет на каждый выбор и не добавляй поля в schema task-status. Реальный запуск выполняет проверенный адаптер; результат проверяется по native metadata.

Кандидаты ниже — каноническое разрешение по роли, не обещание доступности и не новый реестр серверов/подписок. MODELS может явно сузить/заменить набор; сам выбор не редактирует таблицу. Сервер и разрешенный экземпляр берутся из действующего контракта MODELS, автоматически менять их вместе с моделью нельзя. При отсутствии подтвержденного маршрута выбранного провайдера остановись.

| Работа | Альтернативы в порядке проверки; явный effort |
| --- | --- |
| Поиск, извлечение, ограниченная обратимая механика | claude-haiku-5-5/low; gpt-6.1-sol/low; claude-sonnet-5-5/low |
| Требования, SPEC, критерии/тесты | claude-sonnet-5-5/medium; gpt-6.1-sol/medium; gpt-6-astra/medium |
| Архитектура | claude-opus-5-5/medium; gpt-6-astra/high; gpt-6.1-sol/high; claude-sonnet-5-5/high |
| Реализация | claude-sonnet-5-5/high; gpt-6.1-sol/medium; gpt-6-astra/medium; с отдельной проверкой режима записи/patch |
| Обычная независимая сверка | claude-sonnet-5-5/medium; gpt-6.1-sol/medium; gpt-6.1-terra/medium; gpt-6-astra/medium |
| Необратимая/эскалированная сверка, debugger/review | claude-sonnet-5-5/high; gpt-6.1-sol/high; gpt-6.1-terra/high; gpt-6-astra/high; claude-opus-5-5/high при явном разрешении review этой моделью |
| Диагностика, значимые тексты, вычитка | claude-sonnet-5-5/medium; gpt-6.1-sol/medium; gpt-6-astra/medium |
| Учет статусов tracker | claude-sonnet-5-5/low; gpt-6.1-sol/low |

Запрет обработки данных, safety/organization refusal, 401/403 и расходный HOLD не обходятся переходом по кандидатам, аккаунтами, ключами, прокси или серверами. После начавшегося неудачного вызова сначала сохрани реальный результат/usage и оцени частичные эффекты. Timeout, неизвестный результат или незавершенный writer не разрешают запуск второго writer либо применение другого patch в том же дереве. Работающие вызовы не переключай; смена модели/effort при несовместимом resume требует нового контекста.

## Канонические дефолты

Эти значения используются без подходящего назначения MODELS. Сервер по умолчанию - текущая разрешенная среда, если выбранный адаптер в ней проверен; иначе диагностика. Главную модель приложения это правило автоматически не переключает. Для исполнения текущим агентом фиксируй фактическую модель приложения; таблица задает новые делегированные запуски. Явно закрепленное обязательное назначение не обходи; для обычного предпочтения разрешены только альтернативы по алгоритму выше.

| Роль / процедура | Модель | Effort |
| --- | --- | --- |
| architect, planner / requirements | claude-opus-5-5 | medium |
| implementer / этап SDD | claude-sonnet-5-5 | high |
| implement / проверенный Codex writer | gpt-6-astra | medium |
| review / обычное; фактический автор gpt-6.1-sol | claude-sonnet-5-5 | medium |
| review / обычное; фактический автор claude-sonnet-5-5 | gpt-6.1-sol | medium |
| review / необратимый эффект, escalation или debugger/review; фактический автор gpt-6.1-sol | claude-sonnet-5-5 | high |
| review / необратимый эффект, escalation или debugger/review; фактический автор claude-sonnet-5-5 | gpt-6.1-sol | high |
| review / Codex audit, second-opinion, advocate, adversarial, compliance; другой установленный автор, при подтвержденной независимости | gpt-6.1-sol | medium; high при необратимом эффекте, escalation или debugger/review |
| review / отдельно разрешенный Claude reviewer | claude-opus-5-5 | medium; high при необратимом эффекте |
| test-writer, code-reviewer, copy-editor | claude-sonnet-5-5 | medium |
| note-taker, note-writer, summarizer / proofread | claude-sonnet-5-5 | medium |
| debugger | claude-sonnet-5-5 | medium |
| tracker | claude-sonnet-5-5 | low |
| explorer, searcher, librarian | claude-haiku-5-5 | low |

Для review, включая Codex audit, second-opinion, advocate, adversarial и compliance, сначала установи фактическую модель автора. Каноническая независимая пара - gpt-6.1-sol и claude-sonnet-5-5: проверяет противоположная модель, обычный effort - medium. Для необратимого эффекта, escalation и процедуры debugger/review effort - high. Сам факт авторства debugger в обычном исправлении не переводит review в high. При установленном авторе из канонической пары дополнительный hold из-за выбора пары не нужен; остальные ограничения сохраняются. Дефолт для другого установленного автора применим только после проверки независимости.

При неизвестном авторстве останови независимый review до установления фактических авторов. При нескольких известных авторах алгоритм выше может выбрать утвержденную модель, отличную от каждого из них; обоснование запиши. Если такой модели нет, остановись и разреши маршрут с owner либо раздели проверку по авторству. Другая сессия автора и неизвестная actual-модель независимости не дают.

Применимое назначение свежего MODELS имеет приоритет над канонической парой и effort. Само отличие от канона не является конфликтом. Непригодное предпочтение исключается по алгоритму выше с явной причиной; если допустимой альтернативы нет либо замена запрещена, сообщи конфликт и останови зависимый запуск. Скрытно подменять назначение нельзя. Отдельно разрешенный Claude reviewer сохраняет собственное назначение и также проходит проверку независимости.

Маршрутизация не дает дополнительного разрешения на review, расход квоты/бюджета, доступ или расширение scope и не снимает действующие holds. Локальные пользовательские overrides остаются локальными. Изменение публичных дефолтов не разрешает автосинк клиентских канонов или push непроверенного diff.

SDD использует роль соответствующего этапа. Для остальных навыков выбирай роль фактической работы: поиск/инвентаризация - searcher/explorer/librarian; требования и планирование - planner; подготовка текста - note-writer/summarizer; проверка - code-reviewer/copy-editor; изменение кода - implementer; диагностика - debugger. Скрипты конвертации, синхронизации и подсчета не требуют нового вызова модели только из-за наличия навыка. Специализированные llm-ru и jev-decide сохраняют ограничения провайдера, данных и разрешенных моделей; несовместимое назначение дает конфликт, не передачу данных другому провайдеру.

## Запуск и проверка

Перед запуском зафиксируй ревизию MODELS и выбранную строку либо canonical fallback, requested модель/effort/сервер. Разреши алиас в точную модель до запуска. Адаптер обязан уметь применить назначение; native frontmatter роли не разрешает игнорировать MODELS. Непригодный адаптер исключи до запуска по общему алгоритму; если допустимого маршрута нет, сохрани блокер. Не ослабляй permissions и не меняй глобальные настройки.

Передай выбранную модель и effort явно. Машинный профиль сохраняет настройки транспорта/доступа, но его поле model не подменяет выбор из MODELS или канона. Для Codex используй рецепт review/codex.md. При resume перечитай таблицу; если назначение изменилось, нужен новый контекст с handoff, поскольку продолжение наследует прежние модель/effort. Ограничения независимого SDD-compliance сохраняются.

Сохрани actual модель и effort по metadata запуска; неподтвержденное - `unknown`. Запрошенный флаг не является доказательством фактического effort. Для независимой проверки выбранные модели автора/проверяющего должны различаться до запуска, а actual проверяется после. Профили с разными именами и разные сессии одной модели не обеспечивают независимость. При неизвестной actual-модели приемку не объявляй PASS.

Для другой сессии или сервера передавай [контекст исходного проекта](subagents-usage.md#контекст-удаленного-задания). MODELS хранит назначения; правила подготовки пакета находятся по этой ссылке.
