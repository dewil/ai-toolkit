# Использование субагентов

## Автоматические триггеры (без явной просьбы)

Запускай соответствующего субагента сразу, не спрашивая разрешения, если такой агент описан в .claude/agents/. Базовые:

- **searcher** - перед любыми изменениями, если нужно найти файлы, символы, паттерны (grep/glob).
- **explorer** - когда нужно понять связи между модулями или структуру незнакомой части проекта.
- **architect** - когда задача требует глубокого решения по структуре, рефакторинга нескольких модулей или архитектурного выбора.
- **planner** - когда у задачи есть цель и нужна декомпозиция на шаги с критериями готовности, зависимостями, рисками. Универсально для кодинга, проектов, учебы.
- **summarizer** - когда пользователь дал длинный источник (стенограмма, переписка, документ, лекция) и просит сжать в структурированную заметку.
- **tracker** - когда нужно посмотреть статус задач/планов/действий по проекту: что просрочено, кто заблокирован, что давно не двигалось.

Дополнительные агенты могут быть добавлены под тип проекта (кодинг/управление/учеба). Используй их по `description` из их frontmatter.

## Явный триггер дробления

Фразы "используй агентов", "используй субагентов", "через агентов", "раздай агентам", "параллельно через агентов" - сигнал раздробить задачу и делегировать субагентам, а не выполнять последовательно самому.

## Правила запуска

- Перед запуском кратко (1-3 строки) озвучь план: какие подзадачи и какому агенту. Жди подтверждения только если разбиение неочевидно или затрагивает необратимые действия.
- Независимые подзадачи запускай **в одном ответе** несколькими вызовами `Agent` - только так они идут параллельно. Зависимые - последовательно.
- Каждому субагенту давай **самодостаточный бриф**: цель, контекст, конкретные пути к файлам, критерий готовности, формат ответа. Субагент не видит историю чата.
- Подбирай тип под задачу: `Explore` - read-only поиск; `Plan` - проектирование; `general-purpose` - открытые многошаговые задачи; кастомные агенты из `.claude/agents/*.md` - по их `description`.
- Если несколько агентов правят файлы одновременно и могут конфликтовать - запускай с `isolation: "worktree"`.

## Фоновый запуск (`run_in_background`)

Параллельный fan-out (несколько `Agent` в одном ответе) ускоряет работу, но ты все равно ждешь всех агентов, прежде чем продолжить. Если нужно НЕ ждать и заниматься другим - у тула `Agent` есть `run_in_background: true` (тот же флаг, что у Bash): агент уходит в фон, ты продолжаешь свою работу, нотификация приходит по завершении.

Фон оправдан, только когда совпадает три условия:

- задача долгая;
- у тебя есть независимая работа на это время;
- результат не нужен для твоего следующего шага.

Иначе - обычный foreground: если результат кормит следующий шаг, агент быстрый, или заняться нечем - фон ничего не дает. **Дефолт - foreground (параллельный fan-out для независимых подзадач); фон - точечно** под три условия выше.

## Ограничения

- Не дублируй работу субагента: делегировал поиск - не grep'ай то же самое сам.
- Если задача мелкая (1-2 файла, один тип работы) - выполняй сам, скажи: "дробление не нужно, делаю напрямую".
- После завершения дай короткое резюме: что делал какой агент, что изменилось, что осталось.
