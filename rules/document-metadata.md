# Метаданные генерируемых документов

Документ, собранный скриптом и уходящий наружу (заказчику, команде, в переписку), несет свойства файла, которые получатель видит в один клик. Их надо задавать явно: по умолчанию туда попадает инструмент сборки.

## Что задавать

- **Автор** - ник или имя, принятое в проекте. Не библиотека, не хост, не имя из шаблона. Дефолт личного канона - `dwl` (см. `addressing.md`; в форке замени на свой).
- **Заголовок** - осмысленный, обычно первый H1 исходника, а не имя временного файла и не путь к нему.
- **Примечание, комментарии** - пусто. Названию скрипта или библиотеки там не место.
- **Даты создания и изменения** - текущие. Библиотеки подставляют дату своего шаблона (python-docx - 23.12.2013), и свежий документ выглядит файлом десятилетней давности.
- **Прочие поля** (тема, категория, ключевые слова, компания) - пусто, если не заданы осознанно.

## Типовые источники мусора

| Инструмент | Что кладет по умолчанию |
| --- | --- |
| python-docx | `author="python-docx"`, `comments="generated by python-docx"`, дата 2013 г. |
| headless-Chrome (PDF) | `Producer: Skia/PDF`, иногда путь к исходнику в `Title` |
| pandoc, офисные конвертеры | свое название в `Producer`/`Creator`, иногда путь и логин |

## Правило

У правила два адресата, и требования у них разные.

**Пишешь или правишь скрипт-сборщик** - он задает свойства сам, а не по просьбе: автор из параметра, иначе из переменной окружения, иначе из дефолта проекта. Собранный документ не должен зависеть от того, вспомнил ли вызывающий про флаг.

**Собираешь документ существующим скриптом** - выясни, что он проставляет без напоминания, и добери остальное флагами. `scripts/md-pdf.py` - ровно такой случай: `--title` он берет из первого H1 сам, а `/Author` пишет только по `--author`, без флага поле остается пустым. "Скрипт не проставил сам" - не оправдание перед получателем файла.

Молча отдать документ со следами библиотеки - дефект, а не мелочь.

## Проверка после сборки

Часть проверки артефакта, наравне с формулами и ссылками: прочитать свойства собранного файла и убедиться, что там задуманное. Открывать Word или просмотрщик для этого не нужно: docx - это zip, свойства лежат в `docProps/core.xml`; для PDF хватает разбора байтов.

**Грубый греп по PDF не годится - он врет на кириллице** (учебный случай `silent-failure.md`: проверка молчит одинаково в двух противоположных состояниях). Не-ASCII значения Chrome пишет не литеральной строкой в скобках, а hex-строкой UTF-16BE с BOM: `/Title <FEFF041F0440...>`. `grep -a "/Author ("` такую запись не находит по определению и молчит **одинаково** в двух противоположных случаях - когда поле пустое и когда оно заполнено русским текстом. Отсюда ложный вывод "сборщик не проставил заголовок" и починка исправного скрипта. Проверять оба формата сразу:

```python
import re, sys
d = open(sys.argv[1], 'rb').read()
dec = lambda v: bytes.fromhex(v[1:-1].decode())[2:].decode('utf-16-be') if v.startswith(b'<') else v[1:-1].decode('utf8', 'replace')
for key in (b'Title', b'Author'):
    vals = [dec(m.group(1)) for m in re.finditer(rb'/' + key + rb'\s*(<[0-9A-Fa-f]+>|\([^)]*\))', d)]
    print(key.decode(), vals or 'НЕТ')
```

Смотреть **все** вхождения, а не первое: если поле дописано инкрементальным обновлением (так добавляется `/Author`, которого Chrome не пишет вовсе), в файле окажется несколько Info-словарей, и первый будет старым - без автора.

Часть полей инструмент не отдает вовсе: `Producer: Skia/PDF` у headless-Chrome не переопределяется, и это не нарушение - движок печати не тайна. Но неустранимое поле не отменяет проверку остальных: путь к файлу, логин пользователя или чужое имя из шаблона там, где значение задать можно, - недопустимы.
