# Перелинковка в Obsidian-vault'е

Правила связей между заметками. Применять к содержимому vault'а.

## Формат ссылок

- Связи между заметками - всегда `[[wiki-link]]`, не markdown-ссылка `[текст](file.md)`. Wiki-link переживает переименование файла, markdown - нет.
- Видимый текст через пайп: `[[shimano-deore-xt|XT M8100]]`. Используй, когда название файла не вписывается в фразу.
- Ссылка на раздел заметки: `[[note#Раздел]]`. На блок: `[[note#^id]]` (id ставит Obsidian).
- Внешние URL - обычный markdown `[текст](https://...)`. Wiki-link только для внутренних заметок.

## Перед созданием новой заметки

Сначала ищи существующую близкую по теме - иначе vault обрастет дублями ("тормоза", "тормозная система", "тормоза-обзор").

1. Grep по vault'у: имя файла, заголовки H1, `aliases` в frontmatter.
2. Если нашлась близкая - дополни ее, не создавай новую. Если тема шире - создай новую и поставь `[[ссылку]]` между ними.
3. Если у существующей заметки другое имя, но та же сущность - добавь синоним в `aliases`, не создавай дубль.

## Куда ставить ссылки

- В тексте при первом упоминании сущности - `[[ссылка]]`. Повторные упоминания в той же заметке можно без ссылки.
- В конце заметки опционально раздел "Связано" со списком `[[...]]` - сюда то, что не вошло в основной текст естественно, но смежно по теме.
- Не ставь ссылки ради ссылок. Каждая `[[ссылка]]` должна вести к заметке, где читатель найдет полезный контекст по этому слову.

## MOC (map of content)

- Точка входа в раздел vault'а - отдельная заметка-карта (`велосипед-moc.md`, `обслуживание-moc.md`), внутри - тематический список `[[ссылок]]` с короткими пояснениями.
- MOC создаются по мере роста раздела (5+ заметок одной темы), не заранее под пустоту.
- В каждой заметке раздела - ссылка снизу на ее MOC ("часть [[велосипед-moc]]").

## Теги vs папки

- **Папки** - физическая структура vault'а, одна заметка = одна папка. Используй для крупных доменов: `велосипед/`, `здоровье/`, `inbox/`.
- **Теги** - сквозные срезы поверх папок: одна заметка = много тегов. Используй для статусов (`draft`, `archive`), типов (`howto`, `reference`), кросс-тем (`инструмент`, `купить`).
- Не дублируй структуру папок в тегах (`#велосипед/трансмиссия` при том, что заметка лежит в `велосипед/трансмиссия/`) - выбери что-то одно.

## Битые ссылки и сироты

- `[[ссылка]]` на несуществующую заметку - валидный workflow в Obsidian (placeholder "хотел бы написать"). Но регулярно ревизуй такие через `librarian` агента - либо создавай заметку, либо убирай ссылку.
- Заметка без входящих ссылок - сирота. Не страшно для свежесозданных, но если заметка месяц висит без входящих - значит ее никто не находит. Подвяжи ее к MOC или к смежной заметке.
