# Клиент-зонтик: топология проекта и памяти

## Единица проекта - папка клиента

Для заказчика/клиента с несколькими направлениями (управление, код, документация) единицей проекта делать **папку клиента**, а не отдельный репозиторий или подпроект. Папка клиента - единственный корень сессий Claude Code и единственный дом памяти. Подпроекты и код-репы - дети: своей Claude-памяти не держат, память консолидируется в корне клиента.

Почему:

1. **Память привязана к корню и не поднимается вверх.** Claude Code выбирает каталог памяти по хешу пути корня сессии; walk-up по дереву для памяти нет (в отличие от CLAUDE.md). Работа из подпапок и реп фрагментирует контекст клиента по разным слотам.
2. **Непредсказуемость на старте.** При заведении клиента заранее не известно, какие подпроекты/репы и какого типа появятся. Зонтик снимает необходимость предсказывать топологию под каждого.
3. **Разработка бывает client-driven.** Задачи трекера, решения встреч, результаты тестирования живут в управленческом слое и порождают код-фиксы. Сессия, делающая фикс, должна видеть оба слоя сразу - это достижимо только при единой памяти в корне клиента.

## Правила работы

- **Сессии всегда запускать из папки клиента.** Корень сессии = папка клиента.
- **Одна `.claude/memory` на клиента** - в корне зонтика. Так как корень всегда клиент, новая память сама копится в зонтике - роутить ничего не надо.
- **Код-репы - дети через workspace.** Код-репозитории живут в отдельной git-зоне (вне синкаемой папки клиента) и подключаются доп. folder'ом в клиентский мульти-рут `.code-workspace`; правятся оттуда, но корнем памяти остается клиент.
- **`project_type` - список** (например `[management, coding]`): у клиента разные направления, бутстрап специализаций делается на уровне клиента.

## ASCII-токен в имени папки клиента (обязательно)

Claude Code вычисляет каталог памяти, заменяя каждый не-ASCII-алфавитно-цифровой символ пути на дефис (эквивалент `sed 's|[^A-Za-z0-9]|-|g'`). Две соседние папки с не-ASCII именами **равной длины** (например, кириллица) схлопываются в одинаковую строку дефисов -> один и тот же слот памяти -> они молча делят и затирают память друг друга.

Митигация: имя папки клиента должно содержать ASCII-токен (год, код клиента) - тогда слот уникален. Пример: `2026-07 Agent`, а не просто `Агент`.

## Онбординг новой репы/подпроекта в зонтик

1. Добавить папку репы доп. folder'ом в клиентский `.code-workspace`.
2. Если репа уже накопила свою `.claude/memory` - перенести актуальные заметки в память клиента и перестать вести в репе отдельную Claude-память.
3. Дальше сессии - только из папки клиента; своей памяти в репе не заводить.

## Исключение

Репозиторий, чью память надо версионировать в git и шарить с командой, остается независимым проектом со своей памятью. Дефолт - зонтик.
