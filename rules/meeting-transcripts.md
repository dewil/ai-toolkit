# Транскрипции встреч

Если для встреч используются автоматические сервисы транскрипции, типичный набор - два движка, дополняющих друг друга. Хранить рядом, использовать взаимодополняюще.

## Источники транскрипций

- **KTalk (`.txt`)** - встроенная транскрипция. Точные таймкоды и надежная разметка спикеров по ФИО, но слабее распознает русский. **Брать отсюда:** авторство фразы, точные таймкоды, имена спикеров.
- **mymeet.ai (`.md` + `.json`)** - структурированный отчет: супер-краткое, саммари по темам, задачи, транскрипт с таймкодами. **Брать из `.md`:** смысл встречи при чтении глазами. **Брать из `.json`:** для программной обработки - `chapters` (главы с границами в секундах), `word_timings` (поминутные таймкоды слов), второе саммари по шаблону `tasks`, метаданные. mymeet галлюцинирует в шапке (путает имена/стороны), сшивает реплики, укрупняет таймкоды - сверять имена с KTalk.

Старый формат mymeet `.docx` устарел; если встретился - конвертировать в `.md` (через python-docx, маппинг стилей `Heading 4` -> `**название**`, `Heading 3` -> `**секция**:`, `Heading 2` -> `### подсекция`, `List Bullet/Number` -> `-`).

## Где что брать

- **Смысл и чтение глазами:** mymeet `.md`.
- **Точное авторство фразы и таймкод:** KTalk `.txt`.
- **Программная обработка** (главы, точные таймкоды слов, метаданные): mymeet `.json`.
- **Имена и стороны** в mymeet всегда сверять с KTalk (mymeet ошибается).

## Резюме `.summary.md`

Для каждой встречи рядом с raw-транскрипциями кладется файл `<имя-встречи>.summary.md` - верхнеуровневое резюме под отправку заказчику/команде.

- Raw НЕ удалять - это источник истины для спорных формулировок и таймкодов.
- Стиль резюме - верхнеуровневый, не детальный, не как у mymeet (детальный mymeet-стиль не подходит для рассылки).
- Шаблон: тема, дата, участники, ключевые обсуждения, решения с владельцами и сроками, action items, открытые вопросы.
- Имена при первом упоминании - в однозначной форме (ФИО или Имя + Фамилия в скобках), чтобы не путать тезок. См. `name-cross-check.md`.
