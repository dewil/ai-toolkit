# Транскрипции встреч

Если для встреч используются автоматические сервисы транскрипции, типичный набор - два движка, дополняющих друг друга. Хранить рядом, использовать взаимодополняюще.

## Источники транскрипций

- **KTalk (`.txt`)** - встроенная транскрипция. Точные таймкоды и надежная разметка спикеров по ФИО, но слабее распознает русский. **Брать отсюда:** авторство фразы, точные таймкоды, имена спикеров.
- **mymeet.ai (`.md` + `.json`)** - структурированный отчет, но для нас это в первую очередь **источник транскрипта**, а не смысла. **Брать из `.md`:** сам транскрипт (читаемый, с разбивкой по темам). **Брать из `.json`:** структурно-механическое - `chapters` (главы с границами в секундах), `word_timings` (поминутные таймкоды слов), метаданные. mymeet галлюцинирует в шапке (путает имена/стороны), сшивает реплики, укрупняет таймкоды - сверять имена с KTalk.

> **Встроенные самари и задачник mymeet** (супер-краткое, саммари по темам, `tasks`) - **не хранить и не использовать как источник смысла или action items.** У сервиса нет нашего контекста (локальная база, история проекта, договоренности) - он видит одну встречу, поэтому его выводы регулярно ошибочны. Смысл, решения и задачи выводим сами - из транскрипта, сверяя с локальной базой при обработке.
>
> Поэтому от скачанного файла оставляем **заголовок и транскрипт**, служебная шапка не сохраняется. `scripts/mymeet-snapshot.py` режет ее сам по маркеру `**Транскрипт:**`; маркера нет (сменился формат сервиса) - файл сохраняется целиком с предупреждением в stderr, шапку убрать вручную. Обрезка не задним числом: балк-прогон известные встречи пропускает, поэтому забранное раньше остается как есть - чистить, если нужно, руками. Точечный `--pull <ID>` встречу перекачивает и файл перезаписывает (это его смысл - забрать свежую версию после правки имен спикеров), предупреждая об этом в stderr; локальные правки в этом файле при этом теряются.

Старый формат mymeet `.docx` устарел; если встретился - конвертировать в `.md` (через python-docx, маппинг стилей `Heading 4` -> `**название**`, `Heading 3` -> `**секция**:`, `Heading 2` -> `### подсекция`, `List Bullet/Number` -> `-`).

## Где что брать

**Коротко: mymeet = текст транскрипта, KTalk = кто/когда/имена, смысл и задачи = выводим сами из транскрипта + локальной базы.**

- **Транскрипт (чтение глазами, разбивка по темам):** mymeet `.md`.
- **Точное авторство фразы, таймкод, имена спикеров:** KTalk `.txt` (mymeet в именах ошибается - всегда сверять).
- **Программная обработка** (главы, точные таймкоды слов, метаданные): mymeet `.json`.
- **Смысл, решения, задачи:** выводим сами из транскрипта + локальной базы; НЕ из встроенных самари/задачника mymeet.

## Резюме `.summary.md`

Для каждой встречи рядом с raw-транскрипциями кладется файл `<имя-встречи>.summary.md` - верхнеуровневое резюме под отправку заказчику/команде.

- Raw НЕ удалять - это источник истины для спорных формулировок и таймкодов.
- Стиль резюме - верхнеуровневый, не детальный, не как у mymeet (детальный mymeet-стиль не подходит для рассылки).
- Шаблон: тема, дата, участники, ключевые обсуждения, решения с владельцами и сроками, action items, открытые вопросы.
- Имена при первом упоминании - в однозначной форме (ФИО или Имя + Фамилия в скобках), чтобы не путать тезок. См. `name-cross-check.md`.
