# Google Sheets через MCP `google-workspace`

Если в проекте используется MCP-сервер `google-workspace` для чтения/записи Google Sheets - вот рабочие нюансы.

## Чтение и запись

- `mcp__google-workspace__read_sheet_values` - читать диапазон.
- `mcp__google-workspace__modify_sheet_values` - писать. По умолчанию `value_input_option="USER_ENTERED"` - формулы и даты интерпретируются.

## Адресация

- `spreadsheet_id` берется из URL после `/d/`.
- `gid` из URL - это **внутренний sheetId**, а НЕ имя листа.
- В диапазоне (`range_name`) надо указывать **имя листа в одинарных кавычках**, если оно содержит дефисы, пробелы или спецсимволы: `'1-1'!C100`. Без кавычек Sheets API вернет "Unable to parse range".
- Если имя листа неизвестно - не перебирать варианты вслепую: получить список листов через `mcp__google-workspace__get_drive_file_content` (по ID файла) или прочитать без указания листа (вернет первый) и уточнить у пользователя.

## Безопасность записи

- Перед записью **всегда** читать текущее значение ячейки/диапазона, чтобы не затереть данные.
- Если запись сложная (несколько ячеек, формулы) - сначала сделать предпросмотр на тестовом листе, потом писать в основной.

## Аккаунт

- Для всех вызовов `mcp__google-workspace__*` в параметре `user_google_email` использовать **рабочий** Google-аккаунт пользователя. Системный `userEmail` из контекста Claude может не совпадать с рабочим - уточняй и фиксируй в memory.
- Здесь аккаунт передается параметром вызова - это частный случай. Если у сервиса аккаунт зашит в OAuth-сессию самого MCP-сервера и параметром не выбирается (Asana и подобные) - см. `rules/mcp-multi-account.md`.
