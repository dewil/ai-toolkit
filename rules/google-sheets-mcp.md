# Google Sheets через MCP `google-workspace`

Если в проекте используется MCP-сервер `google-workspace` для чтения/записи Google Sheets - вот рабочие нюансы.

## Чтение и запись

- `mcp__google-workspace__read_sheet_values` - читать диапазон.
- `mcp__google-workspace__modify_sheet_values` - писать. По умолчанию `value_input_option="USER_ENTERED"` - формулы и даты интерпретируются.

## Адресация

- `spreadsheet_id` берется из URL после `/d/`.
- `gid` из URL - это **внутренний sheetId**, а НЕ имя листа.
- В диапазоне (`range_name`) надо указывать **имя листа в одинарных кавычках**, если оно содержит дефисы, пробелы или спецсимволы: `'1-1'!C100`. Без кавычек Sheets API вернет "Unable to parse range".
- Если имя листа неизвестно - не перебирать варианты вслепую: получить список листов через `mcp__google-workspace__get_drive_file_content` (по ID файла) или прочитать без указания листа (вернет первый) и уточнить у пользователя.

## Безопасность записи

- Перед записью **всегда** читать текущее значение ячейки/диапазона, чтобы не затереть данные.
- Если запись сложная (несколько ячеек, формулы) - сначала сделать предпросмотр на тестовом листе, потом писать в основной.

## Аккаунт

- Для всех вызовов `mcp__google-workspace__*` в параметре `user_google_email` использовать **рабочий** Google-аккаунт пользователя. Системный `userEmail` из контекста Claude может не совпадать с рабочим - уточняй и фиксируй в memory.
- Здесь аккаунт передается параметром вызова - это частный случай. Если у сервиса аккаунт зашит в OAuth-сессию самого MCP-сервера и параметром не выбирается (Asana и подобные) - см. `rules/mcp-multi-account.md`.

## "Connected" не означает, что инструменты доступны

Прежде чем обещать пользователю правку таблицы, проверь, что нужный инструмент **есть в этой сессии**. Статус сервера этого не показывает: `claude mcp list` отвечает `✔ Connected`, лог сервера чистый, а инструментов при этом может не быть ни одного.

**Признак - не статус, а фактическое наличие инструмента.** Ответ "MCP не подключен", данный по статусу, - неверная диагностика: она отправляет пользователя чинить работающее (`/mcp`, переавторизация), а причина в другом месте. Прецедент: агент трижды за сессию повторил это объяснение, пока не посмотрел, что вообще доступно.

Причины разные, и лечатся по-разному:

- **сервер переподключился в ходе сессии.** Реестр инструментов собирается на старте; после обрыва и восстановления связи он не пересобирается, и инструменты не возвращаются, хотя сервер снова живой. Проверено на этой машине: в начале сессии 45 инструментов `google-workspace` были доступны, после переподключения не осталось ни одного - при неизменной строке запуска;
- **сервер поднялся после старта сессии** - в реестр он не попал по той же причине;
- **сервер запущен с урезанным набором инструментов.** У `workspace-mcp` это ключ `--tool-tier` (`core` / `extended` / `complete`). Проверять строку запуска стоит, но это гипотеза, а не диагноз: на одном и том же `core` инструменты Sheets в одной сессии были, в другой нет.

Порядок диагностики - от дешевого: перезапустить сессию (лечит первые две причины, самые частые); не помогло - смотреть аргументы запуска сервера в конфиге; и там, и там пусто - идти обходным путем ниже.

**Чтение таблицы возможно в обход**, даже когда инструментов Sheets нет: `mcp__claude_ai_Google_Drive__read_file_content` по `fileId` отдает содержимое листа текстом, включая многоуровневую шапку. Для сверки "что сейчас в таблице" этого достаточно; для записи - нет, там `scripts/gsheets.py`.

## Когда записать нельзя: готовь вставку, а не таблицу в чат

Markdown-таблица из ответа в чате при копировании приходит **сплошным текстом** - Sheets кладет всю строку в одну ячейку. Предлагать "скопируй отсюда" бесполезно, и выясняется это только после того, как пользователь попробовал.

Готовь блок с настоящими табуляциями и клади его в файл, который пользователю **видно его инструментами**: в Obsidian-проекте это `.md` с блоком кода - в режиме чтения у блока есть кнопка копирования, отдающая содержимое дословно. Файл во временном каталоге сервера не годится: пользователь его не откроет.

- **пустая ячейка - два подряд идущих табулятора**, а не пробел между ними: пробел запишется в ячейку и испортит формулы и фильтры;
- **указывай якорную ячейку** ("встать на A6") - иначе пользователю считать столбцы самому;
- **несколько блоков - назови порядок**: строки вставляются раньше колонок, иначе колонкам не на что ложиться;
- **фолбэк одной строкой**: "Данные -> Разделить текст по столбцам, разделитель Табуляция" - на случай, если буфер придет размеченным как HTML.

## Когда MCP недоступен или неприменим

У канала есть два штатных отказа, и оба чинятся не настройкой:

- **Инструменты пропадают из сессии** при живом сервере - разобрано выше ("Connected" не означает, что инструменты доступны). Лечится перезапуском сессии, то есть требует человека.
- **Headless и cron.** Интерактивно авторизованный MCP там ненадежен по построению (`mcp-multi-account.md`): протухший токен некому переавторизовать.

Обходной путь - `scripts/gsheets.py`: прямые запросы к Sheets API на stdlib, по своему `~/.config/gsheets/auth.json`. Отдельной интерактивной авторизации не требует.

Этот же путь предпочтителен **независимо** от доступности MCP в двух случаях:

- **нужны формулы, а не значения** (`--formulas`, то есть `valueRenderOption=FORMULA`);
- **большой диапазон**, ответ по которому не влезает в лимит вывода инструмента.

**Смотреть формулы через выгрузку книги в xlsx нельзя.** Экспорт отдает часть формул уже посчитанными значениями: на контрольном образце доехало 44 формулы против 200+ реальных, и лист выглядел как "почти целиком константы". Вывод, сделанный по такому файлу, неверен - причем правдоподобен, а это худший вид ошибки.

Чего обходной путь не дает: `refresh_token` он не добывает. Его надо один раз получить из любого OAuth-клиента с областью `spreadsheets` (проще всего скопировать из хранилища уже авторизованного `workspace-mcp` - это и делает разовый фолбэк скрипта). Интерактивного OAuth-флоу в скрипте нет намеренно: он потребовал бы своего `client_secret` и браузера. Файл учетных данных - секрет по `secrets-handling.md`: вне репозитория, вне синкаемых папок, права 600.
